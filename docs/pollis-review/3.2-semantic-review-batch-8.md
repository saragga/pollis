# 3.2 Semantic review of the code examples, batch 8

Task 3.2 of the Pollis Polish Roadmap. Batch 8 is files 169 to 192 of `LC_ALL=C ls src/vs/workbench/contrib/model/browser/webviews/*.toml`, from `rnn` to `sreg`. All 24 panels were reviewed.

The code was read as `node build/pollis/extractCodeExamples.ts` renders it (`.build/code-examples/<id>/<model>.jl`), covering the default code of every model and every Next Steps action, with each input at its default. No Julia was run; task 3.4 runs the code. Wikis and notebooks are out of scope. Verdicts, finding ratings and the "fixed" rule follow the batch 1 report (`3.2-semantic-review-batch-1.md`). A panel with a finding rated wrong is rated at least questionable, even when that finding is fixed here.

Where a finding depends on a package's API, I checked the package source on GitHub (TextAnalysis.jl for `rouge`), and the finding says so. Items already tracked elsewhere are not repeated: postfix transposes, `bert` token attribution, `rl` Zygote, the `kgds`/`diff` mentions and `rxinfer`'s `gaussian_model`.

## Cross-cutting findings

- **S1. Defaults that switch the feature off.** This batch has more of these than any before it (U1 in batch 6, T2 in batch 7).
  - `sgo` minimised a single convex bowl starting at its minimum (fixed).
  - `sid` ran parallel tempering on a single Gaussian (fixed).
  - `sreg` searched for a law in three collinear points that many formulas fit exactly (fixed).
  - `sdea`'s first-passage threshold was 6.7 standard deviations away, so no path crossed it (fixed).
  - `rzoo`'s sweep and simulation start at rest, where nothing moves (the sweep is fixed).
  - `so` starts where the Hessian is already positive definite, so Newton's weakness never shows.

  The same question catches all of them: on the default data, could this action's result have come out otherwise?
- **S2. Checks that cannot fail.**
  - `rqr`'s "share of residuals below zero matches tau" and its in-sample coverage of the fitted 5% and 95% quantiles both hold by construction.
  - `sdea` averaged censored first-passage times as if they were observed (fixed).
  - `sdea`'s noise comparison plotted mean paths, which a linear drift makes identical (fixed).
- **S3. Code that cannot run as written.**
  - `rsm` rendered `Xg =` with nothing after it (fixed).
  - `slm` rebinds the package function `tokens` (fixed).
  - `smc` wrote `Particle.[]` (fixed).
  - `sgo` never set the local optimiser MLSL requires (fixed).
  - `rouge` calls functions and fields TextAnalysis does not have.
  - `sid` needs recorders and a reference that are never given.
  - `smc` reads SMCIO fields that do not exist.
- **S4. Actions that ignore the selected model.** In `si`, `sde`, `sgo`, `slm` and `rzoo`, actions fit one fixed model or call functions defined only in some branches.
- **S5. In-sample evaluation.**
  - `rp` computes adjusted R2 and a test-mean R2 on test data.
  - `si` computes fit percentages on the estimation data.
  - `rnn` compares its linear baseline on training MSE.
  - `sreg` chooses the best expression by training loss.
- **S6. Zygote and non-ASCII.**
  - `rnn`'s Flux training uses Zygote.
  - `rsm` has a `÷` in code.
  - `rp` has an `R²` in a comment.

## Panel reviews

### rnn: Recurrent Neural Networks

**Sound, adequate.** GRU, LSTM, a GRU encoder with multi-head attention, and an echo state network with a closed-form ridge readout (spectral-radius rescaling and leaky update correct). Actions include fit and hidden-state plots, held-out error, recursive multi-step forecasts, a linear baseline and saliency.

1. **Questionable (S6).** `Flux.train!` and the saliency gradient use Zygote.
2. **Questionable. Action `training-curve` (ESN).** It plots training MSE against the ridge penalty, which rises by construction. Choose the penalty on held-out sequences.
3. **Questionable (S5). Action `linear-baseline`.** It compares on training MSE with a network of about 15,000 parameters. The architectures are never compared with each other.

### ropt: Uncertainty-Set Robust Optimisation

**Sound, rich.** A production LP under box, ellipsoidal, Bertsimas-Sim budget and polyhedral uncertainty sets. I checked the robust counterparts and worst-case protections: sum d, Omega ||d||, the Gamma largest deviations, and Gamma max d via LP duality over all sign vectors. Actions include the robust frontier, feasible regions, worst cases, the price of robustness against simulated violation probability, the scenario approach, all sets together, conservatism and shadow prices.

1. **Questionable. Action `price-robustness`.** It always uses the box set. The simulated violations assume independent uniform deviations, which the box set protects against fully and the others only probabilistically. State each set's guarantee.

### rouge: ROUGE Evaluation

**Wrong, thin.** ROUGE-1, ROUGE-2, ROUGE-L and ROUGE-S with TextAnalysis.

1. **Wrong, not local (S3).** I checked TextAnalysis's `evaluation_metrics.jl`. `rouge_n(references::Vector{String}, candidate::String, n)` scores one candidate against its references and returns `Score` values with fields `precision`, `recall` and `fmeasure`. The panel gets this wrong in several ways:
   - it passes a corpus of candidates first;
   - it uses a `beta` keyword that does not exist;
   - it reads `.f1`, which is not a field;
   - it calls `rouge_l` and `rouge_s`; the package has `rouge_l_sentence` and `rouge_l_summary`, and no ROUGE-S.

   Nothing runs.
2. **Questionable. Action `aggregate-scores`.** "Micro and macro averages" computes only the macro average.
3. **Questionable. Action `compare-systems`.** It ranks systems by mean F1 with no uncertainty.

**Proposal (thin).** The panel should answer: is summariser A really better than summariser B on this set of documents, and on which kinds of overlap? Score each document's candidate against its references with `rouge_n` (1 and 2) and `rouge_l_summary`, and report precision, recall and F. Compare two systems with a paired bootstrap over documents, reporting the difference and its interval, not only the two means. Show one or two documents where ROUGE and a human reading disagree (paraphrase, wrong facts) to make its limits concrete.

### rp: Regression Performance

**Questionable, thin.** RMSE, MAE, R2, adjusted R2 and MAPE on `y_test` and `y_hat`, with residual, Q-Q, predicted-against-actual and error-histogram plots.

1. **Questionable (S5).** Adjusted R2 penalises in-sample fit for fitted parameters, so on a test set it has no meaning. Test R2 uses `mean(y_test)` as its baseline, which peeks at the test data; use the training mean.
2. **Questionable.** MAPE explodes near zero, which is not stated. The Q-Q plotting positions `range(0.01, 0.99)` are not (i - 0.5)/n. The comment "adjusted R²" contains non-ASCII (S6).

**Proposal (thin).** The panel should answer: is this model's test error good, compared with what, and how sure are we? Have the default code fit two models (a mean-only baseline and a linear model) on a training split of shipped data. Then report on the test split:
- RMSE, MAE and test R2 (training-mean baseline) for both;
- bootstrap intervals for each metric;
- a paired test of the difference in squared errors.

Keep the residual diagnostics.

### rqr: Robust and Quantile Regression

**Questionable, rich.** Quantile regression and M-estimation. Actions include the quantile process against OLS, IRLS weights, leverage (with the correct warning that neither estimator protects against high-leverage covariates), a 90% band from the 5% and 95% quantiles, alternative losses, Wald intervals and the Koenker-Machado pseudo R2.

1. **Questionable (S2). Action `weights` (quantile).** "The share of residuals below zero should match tau" holds by construction: the first-order condition of quantile regression puts about tau n residuals below zero. This check cannot fail.
2. **Questionable (S2). Action `interval`.** The in-sample coverage of bands made of fitted quantiles is 0.90 for the same reason. Measure coverage on held-out rows.
3. **Questionable.** Wald intervals for quantile coefficients depend on a sparsity estimate whose method is not stated; the bootstrap is safer.

### rsm: Regime Switching Models

**Questionable, rich.** Markov-switching regression, AR, ARCH and time-varying-transition models (MarSwitching.jl). Actions include filtered and smoothed probabilities, residual tests, restarts for local maxima, forecasts without look-ahead, simulated VaR, AIC/BIC across the number of regimes, a specification search, durations and ergodic shares.

1. **Wrong, fixed (`90fa187f`) (S3). Action `grid`.** For the `msm`, `msarch` and `tvtp` models it rendered `Xg = ` with nothing after it, because the switching-regressors input defaults to empty; the next line was swallowed. `Xg` is now set only when regressors are given, and an error explains otherwise.
2. **Questionable.** Choosing the number of regimes by AIC/BIC is not justified by standard theory, because the extra regime's parameters are unidentified under the null. Residuals from the probability-weighted fit are not i.i.d. even under the true model. `length(r) ÷ 4` is non-ASCII (S6).

### rulebased: Rule-Based Methods

**Questionable, adequate.** Frequent itemsets and association rules with RuleMiner. Actions include top patterns, support against confidence coloured by lift, a threshold sweep, the lift <= 1 share, recommendations, algorithm timing, closed and maximal itemsets, and the strongest rules.

1. **Wrong, fixed (`a242bce9`).** The comments listed output columns that differ from RuleMiner's `Itemset`, `LHS`, `RHS`, `Support`, `Confidence`, `Coverage`, `Lift`, `N` and `Length`, which the actions use.
2. **Questionable.** `Txns(df, ...)` takes a DataFrame and returns DataFrames, against the no-DataFrames rule. Lift ranks tiny-support rules highly; show support and a significance measure next to it.

### rvol: Range-Based Volatility Estimation

**Sound, rich.** Parkinson, Garman-Klass, Rogers-Satchell, GK-Yang-Zhang, Yang-Zhang and Alizadeh-Brandt-Diebold (log range mean log sigma + 0.43, sd 0.29, correct) against close-to-close. Actions include:
- rolling estimates;
- clustering;
- drift and overnight-gap checks that choose the estimator;
- a forecast with square-root-of-time scaling;
- an out-of-sample backtest;
- textbook efficiencies;
- a GARCH comparison and empirical efficiency.

1. **Questionable.** The inputs `open` and `close` shadow `Base.open` and `Base.close`. The backtest's realised-volatility proxy is close-to-close, which favours the close-to-close forecast.

### rxinfer: Fast Variational Bayesian Inference

**Questionable, adequate.** A conjugate Gaussian, Bayesian regression and a streaming tracker by VMP. Actions include marginals, free energy, convergence, prior sensitivity, the posterior predictive, VMP against NUTS, and model comparison. The `gaussian_model` calls in the regression and streaming branches are already tracked.

1. **Wrong, fixed (`99246553`). Action `model-comparison`.** It promised a Gaussian-against-Laplace comparison but fits only one model, and it called lower free energy a "better fit". The description and comments now say what is computed; free energy is an upper bound on -log evidence.
2. **Questionable.** With unknown mean and precision, RxInfer needs a mean-field constraint and an initialisation, and the likelihood should be `Normal(mean = mu, precision = tau)`, not `Normal(mu, sqrt(1/tau))` (task 3.4 will hit this).
3. **Questionable. Action `vmp-vs-mcmc`.** It compares means only, while mean-field VMP's known weakness is understated variance.
4. **Questionable. Model `streaming`.** It resets the precision prior at every observation.

### rzoo: RobotZoo Robot Model Library

**Questionable, thin.** RobotZoo's bicycle, cart-pole, pendulum and quadrotor (hover thrust m g / 4, correct). Actions include simulation, finite-difference linearisation, an ALTRO setup, a parameter sweep and dimensions.

1. **Wrong, fixed (`2a2ba457`) (S1). Action `param-sweep`.** It evaluated the pendulum at the default state (hanging at rest, no torque), where xdot = 0 for every mass. It also ran the pendulum for any model and promised trajectories. It now starts at 45 degrees, runs only for the pendulum, and has an honest description.
2. **Questionable (S1). Action `simulate-plot`.** It also starts at rest with zero control, so every plot is flat lines.
3. **Questionable.** `x_eq`, `u_eq` and `xf` are undefined. The bicycle's state and control order should be checked against RobotZoo.

**Proposal (thin).** The panel should answer: what does each benchmark robot do on its own, and what does it take to stabilise it? For the pendulum and cart-pole, simulate from a displaced state with an energy check. Linearise at the upright equilibrium and show the unstable eigenvalue. Then close the loop with an LQR gain from the linearisation and simulate the recovery. For the quadrotor, show hover trim and the response to a thrust imbalance. Drop the ALTRO snippet or make it complete for one model.

### sbi: Simulation-Based Inference

**Sound, rich.** Amortised neural estimation (NeuralEstimators.jl, DeepSets) on a Normal test model. Estimators include a point estimator with bootstrap intervals, an interval estimator and a quantile estimator. Actions include estimates against truth, bias/RMSE, coverage over the prior (the right calibration check), the closed-form MLE as a benchmark, and RMSE against replicates.

1. **Questionable. Action `mle`.** It defines `values(Z, k)`, shadowing `Base.values`.
2. **Questionable. Action `rmse-vs-m`.** An estimator trained at m = 150 is applied from m = 37 to 300 without a word about extrapolation. A model without a tractable likelihood would show why one uses this method.

### sbo: Surrogate-Based Optimisation

**Sound, rich.** Three surrogates, written out:
- Kriging with expected improvement (EI correct);
- a cubic RBF with a linear tail;
- a quadratic response surface.

All start from a Latin hypercube. Actions include leave-one-out and fresh-point accuracy, exploration, initial-design size, multi-start, polish, a Surrogates.jl comparison, budgets, and direct search at the same budget.

1. **Questionable.** Rosenbrock spans four orders of magnitude, which a GP on standardised y fits poorly; model a log-transformed objective. The signal variance is fixed at 1, and only six length scales are tried.

### sde: Diffusion Processes

**Questionable, adequate.** Scalar SDEs (additive OU, multiplicative, Stratonovich). Actions include paths, an ensemble, strong convergence, mean and variance, Ito against Stratonovich on a shared path, and the stationary distribution.

1. **Wrong, fixed (`22ff82fd`). Action `stationary`.** The stationary variance was written `sigma^2 / 2*theta`, which reads as sigma^2 theta / 2. It is sigma^2 / (2 theta), 0.09 here.
2. **Questionable. Action `convergence`.** `analyticalsolution_vs_numerical` is not a DiffEqDevTools function (`test_convergence` is). For additive noise, EM has strong order 1, which is worth saying.
3. **Questionable.** Mean and variance are never compared with their closed forms. The stationary histogram includes the transient, and `plot(h, normalize=:pdf)` does not normalise a Histogram. Actions hard-code the diffusion (S4).

### sdea: SDE Ensemble Analysis

**Questionable, adequate.** First-passage times, the invariant distribution and path statistics for an OU process. Actions include fan charts, convergence in N, quantile bands, a noise comparison, and the Fokker-Planck density against the empirical one (formula correct).

1. **Wrong, fixed (`aec419b1`) (S1, S2). Model `fpt`.** The default threshold 2.0 is 6.7 stationary standard deviations above the mean, so paths essentially never crossed it, and every "first passage time" was the 1000-unit horizon, averaged in as if observed. The default is now 0.0 (the long-run mean), and paths that never cross are counted and excluded as censored.
2. **Wrong, fixed (same commit) (S2). Action `compare-noise`.** It plotted mean paths, which are e^(-0.5 t) for every sigma; it now plots the standard deviation across paths.
3. **Questionable.** Convergence in N prints no Monte Carlo standard error. The fan chart's ±2 sd band is a band for individual paths, not a confidence band for the mean. The analytic moments are never used as a check.

### sgm: Stochastic Gradient Methods

**Sound, rich.** SGD, AdaGrad, Adam and AdaMax (Optimisers.jl, with gradients by Enzyme) on an ill-conditioned quadratic with gradient noise. Actions include the noise floor, iterates on contours, learning-rate sensitivity, a stationarity check, Polyak-Ruppert averaging, and six methods over 5 seeds.

1. **Questionable. Action `compare-sg-methods`.** Every method runs at learning rate 0.01, which suits some rules and not others; compare each at its best rate from the sweep.

### sgo: Stochastic Global Methods

**Wrong, adequate.** Global search with NLopt (AGS, CRS, MLSL, StoGO, StoGO-R), simulated annealing and basin hopping. Actions include the landscape, convergence, search points, budget, restarts, local polish, multistart and comparisons.

1. **Wrong, fixed (`88933d09`) (S1). Input `obj`.** The default objective x1^2 + x2^2 is a single convex bowl whose minimum is the box midpoint where every search starts. It is now the Rastrigin function on an off-centre box.
2. **Wrong, fixed (same commit). Models `stogo` and `stogo-r`.** They left the gradient unfilled, so StoGO searched with zero gradients; ForwardDiff now supplies it.
3. **Wrong, fixed (same commit) (S3). Model `mlsl` and action `crs-vs-mlsl`.** `GN_MLSL_LDS` needs a local optimiser, which neither set, so NLopt stops with an error; BOBYQA is now set.
4. **Questionable (S4).** Several actions assume the wrong model:
   - `landscape` calls `obj([x, y])` with one argument, which fails for the NLopt models;
   - `solution` and `local-refine` use `result` and `obj_nlopt`, which are defined only in the Optim branches or nowhere;
   - `eval-budget` never installs its counting objective, so it reports 0 evaluations;
   - CRS restarts vary x0, which CRS barely uses.

### si: System Identification Methods

**Questionable, adequate.** ARX, ARMAX, OE and N4SID with ControlSystemIdentification. Actions include Bode and pole-zero plots, residual whiteness, fit percentage, simulation, k-step prediction, order selection, and parameter covariance.

1. **Questionable (S4).** Every action refits ARX(2, 2, 1) whatever the model.
2. **Questionable (S5). Action `fit-percent`.** Fit percentage is computed on one-step predictions of the estimation data, and it is described as "percent variance explained" although it is a norm ratio. Order selection and diagnostics use estimation data only.
3. **Questionable. Action `simulate`.** It builds `u_new` and then plots the old data.

### sid: Sampling from Intractable Distributions

**Wrong, thin.** Parallel tempering with Pigeons.jl on a custom target.

1. **Wrong, fixed (`8ad41014`) (S1). Input `log-p`.** The default target was a standard Gaussian, which one chain samples easily. It is now an equal mixture of unit Gaussians at (3, 3) and (-3, -3).
2. **Wrong, not local (S3).** Three calls fail as written:
   - `get_sample(pt)` needs the `traces` recorder, which no call sets;
   - a custom target also needs a reference distribution;
   - `ess` is not a StatsBase function.
3. **Questionable.** The panel never shows the swap-rate profile or the global communication barrier that Pigeons reports and uses to choose `n_chains`.

**Proposal (thin).** The panel should answer: when does a single MCMC chain fail, and how does tempering fix it? Show the bimodal target sampled by one slice-sampler chain, which stays in one mode, and by Pigeons PT with `record = [traces, round_trip, index_process]` and a Gaussian reference. Compare:
- the share of samples in each mode (0.5 by symmetry);
- round trips;
- the communication barrier Lambda and the swap-acceptance profile;
- ESS from MCMCDiagnosticTools.

Then move the modes further apart and show how n_chains must grow.

### slm: Statistical Language Model

**Wrong, thin.** Unigram, bigram and trigram models with add-k smoothing (TextAnalysis).

1. **Wrong, fixed (`cad9ee15`) (S3). All snippets.** Every snippet assigned `tokens = vcat([tokens(d) for d in crps]...)`, rebinding TextAnalysis's `tokens` in the statement that calls it; the variable is now `toks`.
2. **Wrong, fixed (same commit). Action `perplexity`.** It stopped at the cross-entropy and now also reports 2^H. Two actions used `mean` without `Statistics`.
3. **Questionable (S4).** Every action uses unigram probabilities only; the bigram and trigram models are never evaluated, and `compare-orders` computes nothing. `compare-smoothing` calls an undefined `perplexity` function, and the MLE perplexity is infinite when any test word is unseen, which is the point to state.

**Proposal (thin).** The panel should answer: how much does context help predict the next word, and what does smoothing cost and buy? Split a shipped text corpus into training and test sets. Fit unigram, bigram and trigram models with add-k and with interpolated (Jelinek-Mercer) smoothing, tuning k and the weights on a validation slice. Report test perplexity for each order, the out-of-vocabulary rate, and a few generated sentences per order. Show that the MLE bigram model has infinite perplexity on the test set.

### smc: Sequential Monte Carlo

3. **Questionable.** The model has no observations (lG = -0.5 x^2 is a fixed potential), so "E[x_t | y_1:t]" describes nothing observed. A linear-Gaussian model would allow a Kalman check. Weights are exponentiated without normalising. `ess-trajectory` computes a meaningless, unused `ess_t`.

### so: Second Order Methods

### sreg: Symbolic Regression

**Wrong, adequate.** SymbolicRegression.jl. Actions include the Pareto frontier, fit and residuals, operator, size and iteration comparisons, and feature usage.
