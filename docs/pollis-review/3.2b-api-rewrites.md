## gmm: Generalized Method of Moments

**Invented calls.** `fit(GMM(Heteroscedastic()), df; response, regressors, endogenous, instruments)`, `fit(IV(...), ...)`, `fit(OLS(...), ...)`: Microeconometrics.jl has no `GMM` type and no such keyword interface. Microeconometrics itself cannot be installed today: every version requires DataFrames 0.21 or older (checked in the General registry).

**Real API used.** GMMTools.jl 0.1.0 (Gabriel Kreindler, https://github.com/Gkreindler/GMMTools.jl), read from its source:
- `GMMTools.fit(data, mom_fn, theta0; W = I, mode = :onestep | :twostep, opts = GMMOptions(...))` returns a `GMMFit` with `theta_hat`, `obj_value`, `n_obs`, `n_moms`, `W`.
- `GMMTools.vcov_simple(data, mom_fn, fit)` stores the sandwich covariance in `fit.vcov.V` (moment covariance m'm/n, so heteroskedasticity-robust).
- `GMMTools.boot_weights(data, fit; method = :user, boot_weights_fn, nboot)` and `GMMTools.vcov_bboot(data, mom_fn, theta0, fit, weights; W, run_parallel, opts)` give a Bayesian bootstrap covariance. The built-in `:cluster` method needs a DataFrame, so the panel passes its own cluster weight function (`:user`), which works with any Tables.jl table.
- In the two-step mode the second-step weight is inv(m'm/n) at the first-step estimate, so Hansen's J is `n_obs * obj_value`.

GMMTools is not in the General registry; it was added to `UNREGISTERED_PACKAGE_URLS` in `model.handler.ts`, so the install button uses its URL. It depends on DataFrames and Revise (installed, never used by the panel code) and declares no version bounds, so a future dependency release could break it. It holds FixedEffectModels at 1.13.3 in a shared environment.

**Changes.**
- Moment conditions are written out: `mom_fn(d, theta) = d.Z .* (d.y .- d.X * theta)`, with the constant and the exogenous regressors among the instruments (the old code had no intercept).
- Data: any Tables.jl table, read with `Tables.getcolumn`. With the default name `df`, the code simulates 200 firms over 5 years (log sales on log advertising, which is endogenous through an unobserved demand shock; two advertising-price instruments; firm-clustered, heteroskedastic errors). True coefficients 2.0, 0.5, -0.3, 0.25.
- Input `vcov` (id kept) is relabelled "Estimator": two-step efficient GMM (`het`), one-step GMM with 2SLS weights (`hom`, which was mislabelled as homoscedastic GMM), two-step with cluster bootstrap standard errors (`clustered`). Labels title-cased.
- Actions now reuse the fit from the default code instead of re-fitting six times.
- `first_stage` now computes the partial F of the excluded instruments for every endogenous regressor (batch 4, finding 3).
- `gmm_vs_2sls` no longer promises smaller GMM standard errors; it explains when two-step GMM is more efficient and cites Windmeijer (2005) (batch 4, finding 4).
- `j_statistic` uses the two-step objective, re-estimating two-step GMM when the one-step estimator is selected, and warns that J assumes independent observations in the clustered case.
- New Compare action `ols_vs_gmm`: OLS, GMM and, for the simulated data, the true coefficients.
- Interpret actions explain the effect, the exclusion restriction and what a confidence interval means.
- References added: Windmeijer (2005), Rubin (1981).

**Out of scope.** The four gmm notebooks are "Coming soon!" placeholders, and `media/wiki/gmm/` is empty although the panel lists six wiki pages. No notebook or wiki mentions Microeconometrics.

## tsls: Two-Stage Least Squares

**Invented calls.** `fit(IV(Homoscedastic() | Heteroscedastic() | Clustered(:c)), df; response, regressors, endogenous, instruments)` and `fit(OLS(...), ...)`: not the Microeconometrics API, which cannot be installed anyway (see gmm). The rendered `[:{{exog}}]` was also broken (`[:x1 x2]`), and the model had no intercept (batch 9, findings 1 and 2).

**Real API used.** FixedEffectModels.jl 2.1.0, the current registered release, and 1.13.3, the version GMMTools holds it at. The two are identical for every call used.
- `reg(data, formula, vcov)` accepts any Tables.jl table (it converts internally) and adds the intercept itself.
- The formula is built from the input names with StatsModels' `term` (re-exported): `term(:y) ~ x1 + x2 + (w1 ~ z1 + z2)`, which is the package's IV syntax.
- Standard errors: `Vcov.simple()`, `Vcov.robust()` (HC1), `Vcov.cluster(:c)`.
- The fitted model has fields `F_kp` and `p_kp`: the Kleibergen-Paap first-stage F and p-value, computed with the selected standard errors.
- Other calls used: `residuals(m, data)` (structural residuals, using the observed endogenous regressors), `coef`, `vcov`, `stderror`, `coefnames` (exogenous then endogenous), `confint` (t critical values), `coeftable`, `nobs`, `r2`, `dof_residual`.

FixedEffectModels depends on DataFrames internally; the panel code never uses it.

**Changes.**
- Data: any Tables.jl table. With the default name `df`, the same simulated example as gmm (log sales on log advertising with an unobserved demand confounder; true coefficients 2.0, 0.5, -0.3, 0.25), so OLS is biased and 2SLS recovers the truth.
- Input `vcov` (id and values kept) relabelled "Standard Errors": Robust (HC1), the new default, then Classical (Homoskedastic) and Clustered. Labels title-cased.
- Actions reuse the default fit instead of refitting the same model six times (the "thin" verdict).
- `first_stage`: a Wald F of the excluded instruments for every endogenous regressor, with the selected standard errors, plus the joint Kleibergen-Paap F (batch 9, finding 5; the old code had no F and used only the first regressor).
- New `endogeneity`: Durbin-Wu-Hausman test through the control-function regression, robust to the selected standard errors.
- New `overid`: Sargan n R^2 test, which says when the model is exactly identified and points to the GMM panel's Hansen J as the robust version.
- `residuals`: structural residuals, SD with n - k, and a heteroskedasticity check.
- `ols_comparison` moved to a new Compare group: OLS vs 2SLS, plus the true coefficients for the simulated data. The gap is explained, not presented as a test.
- `vcov_matrix` was replaced by Compare `se_comparison`: the same estimates with classical, robust and, when selected, clustered standard errors. The old action only printed the diagonal of `vcov`, which `coef_table` already shows.
- Interpret: `coef_table` prints the package's coefficient table, then explains the effect, the exclusion restriction and the LATE reading. `confint` explains what a confidence interval means. The new `anderson_rubin` gives a weak-instrument robust 95% set by test inversion over a grid of 8 standard errors either side, and flags gaps and possibly unbounded sets.
- References added: Anderson and Rubin (1949), Hausman (1978), Staiger and Stock (1997), Kleibergen and Paap (2006).
- Of the batch 9 proposal, only the weak-instrument sweep was not added.

**Out of scope.** The four tsls notebooks are "Coming soon!" placeholders. The six wiki pages are three-line stubs. No notebook or wiki mentions Microeconometrics.

## po: Portfolio Optimisation

**Invented calls.** `Portfolio(; returns)`, `optimise!(port, Trad(; obj, rm))`, `optimise!(port, HRP())`, `port.weights`, `MinRisk()`, `CVaR()`: this is the retired PortfolioOptimiser.jl (singular) API, not PortfolioOptimisers.jl. `efficient_frontier!`, `risk_contribution(port)` and `rolling_sharpe` exist in neither (batch 7, finding 1).

**Real API used.** PortfolioOptimisers.jl 0.32.0, the current registered release, read from its source (commit ac537aec):
- Data and solver: `ReturnsResult(; nx, X)` (asset names must be strings) and `Solver(; name, solver = Clarabel.Optimizer, settings, check_sol)`.
- Optimisers: `MeanRisk(; opt = JuMPOptimiser(; slv), r, obj)` with `MinimumRisk()`, `MaximumRatio(; rf)` and `MaximumUtility(; l)`; `HierarchicalRiskParity(; r)` and `HierarchicalEqualRiskContribution(; ri, ro)`; `EqualWeighted()` and `InverseVolatility()` as benchmarks. `optimise(est, rd)` returns a result with `w`, `pr` (the fitted prior) and `retcode`.
- Risk measures: `Variance()` (w' Sigma w), `StandardDeviation()`, `ConditionalValueatRisk(; alpha)`. `MaximumRatio` divides by the model's own risk expression, so a maximum Sharpe portfolio needs `StandardDeviation()`, not `Variance()`.
- Efficient frontier: `ArithmeticReturn(; settings = JuMPReturnsSettings(; lb = Frontier(; N)))` passed as `ret` to `JuMPOptimiser`. `w` and `retcode` then hold one entry per point.
- Metrics: `expected_risk(r, w, pr)`, `expected_return(ArithmeticReturn(), w, pr)`, `expected_risk_ret_ratio(r, ret, w, pr; rf)` and `risk_contribution(r, w, pr)` (Euler contributions that add up to the risk). Passing the prior lets the package fill the covariance into `Variance()`. A bare `Variance()` with a returns matrix fails.
- Walk-forward: `cross_val_predict(est, rd, IndexWalkForward(train, test))` refits on each window. `pred.mrd.X` is the vector of held-out daily portfolio returns, concatenated across folds.

PortfolioOptimisers depends on DataFrames internally; the panel code never uses it. Its plotting recipes need StatsPlots and GraphRecipes, so the panel plots with Plots directly. Clarabel (registered) was added as the conic solver.

**Changes.**
- Every model now runs its own optimiser. The old actions all re-ran `Trad(rm = Variance())` whatever model was selected (finding 2). Actions reuse the default fit (`est`, `res`, `w`, `pr`, `rm`).
- Data: a T x N matrix of daily returns, stated in the tooltip with the 252-day annualisation. With the default name `R`, the code simulates 1,000 days for 8 assets in two sectors, with market and sector factors and Student-t (5 df) shocks. True annualised means are 12% (Tech) and 6% (Util).
- Input `obj` is now a select: Minimum Risk, Maximum Risk-Adjusted Return (Sharpe for Mean-Variance, STARR for Mean-CVaR) and Maximum Utility. New inputs: Risk Aversion (l), CVaR Tail Probability (alpha) and Risk-Free Rate (Annual), which is used, as a daily rate, in every ratio and excess return. Labels title-cased.
- `efficient-frontier`: a real 30-point frontier in annualised volatility and return. It marks the minimum-variance portfolio, the maximum Sharpe portfolio (which the old code never located) and the capital market line from the risk-free rate. It also shows the current portfolio and the single assets, so HRP, HERC and CVaR portfolios can be seen relative to the frontier.
- `risk-contribution`: Euler risk shares under the model's own risk measure, against capital weights.
- `rolling-sharpe`: a 126-day rolling Sharpe ratio of excess returns, labelled as in-sample.
- `oos-performance`: a walk-forward backtest (504-day training window, 63-day holding period, refitted each fold) replaces the single 50/50 split. It reports the annualised excess return, volatility, Sharpe ratio with Lo's (2002) standard error, and the maximum drawdown, and plots wealth (finding 4).
- `compare-equal-weight` and `compare-methods`: out-of-sample on identical walk-forward folds, not in-sample (finding 3). The first tests the Sharpe difference against 1/N (Jobson-Korkie with Memmel's correction). The second covers minimum variance, maximum Sharpe, minimum CVaR, HRP, HERC, inverse volatility and 1/N, with standard errors and drawdowns.
- `portfolio-weights`: sorted weights and the effective number of assets. `expected-risk-return`: in-sample annualised figures from the package, the daily CVaR and, for simulated data, the true expected return of the chosen weights, with a warning that in-sample figures overstate performance.
- `using Statistics` wherever `mean`, `std` or `cor` are used; StatsBase dropped (finding 4).
- References added: DeMiguel, Garlappi and Uppal (2009); Lo (2002).

**Out of scope.** The four po notebooks are "Coming soon!" placeholders, and the ten wiki pages are three-line stubs. None of them mentions either package.

## bfmb: Fama-MacBeth Regression

**Invented calls.** `BayesianFM(f, R; psi0, d, intercept, sim_length, burnin)` and the fields `result.lambda` and `result.R2_oos`. `BayesianFM` takes `(f, R, sim_length; seed)` and nothing else. `psi0`, `d` and `intercept` belong to `BayesianSDF`, and no function in the package has `burnin` (batch 1, finding 1). The bullet described a "normal shrinkage prior", which `BayesianFM` does not have. The actions used the real `lambda_ols_path` and so described a different estimator from the default code.

**Real API used.** BayesianFactorZoo.jl 0.1.0, the registered release; the installed tree hash matches the registry. Read from its source:
- `BayesianFM(f, R, sim_length; seed)` returns `lambda_ols_path` and `lambda_gls_path` (draws x (1 + K); column 1 is the common intercept), plus `R2_ols_path` and `R2_gls_path` (adjusted R2). Each draw takes Sigma from an inverse Wishart and mu from a normal (flat priors), then re-runs the cross-sectional regression on the implied betas. The draws are independent, so there is no chain and no burn-in.
- `TwoPassRegression(f, R)` returns `lambda`, `lambda_gls`, `t_stat`, `t_stat_gls` (Shanken-corrected), `cov_lambda`, `cov_lambda_gls`, `R2_adj`, `R2_adj_GLS`, `alpha`, `t_alpha`, `beta` (N x K) and `cov_beta` (kron(cov_epsilon, (X'X)^-1)).
- Both functions need `Matrix{Float64}`, so the inputs are converted.

**Changes.**
- The Bayesian default code calls `BayesianFM` correctly. The inputs `psi0`, `d`, `intercept` and `burnin` were removed because `BayesianFM` has no such parameters (the proposed fix that the review left for confirmation). "MCMC draws" became "Posterior Draws". The tooltip explains that the draws are independent.
- The input `estimator` (OLS/GLS) now applies to both models; `BayesianFM` returns both paths. Labels title-cased.
- Data: with the defaults `f` and `R`, the code simulates 600 months of Market (premium 0.6% per month), Value (0.3%) and a useless factor that no portfolio loads on, plus 25 portfolios on a 5 x 5 beta grid with exact pricing. This makes the panel's main point visible: the two-pass method can make a useless factor look priced, while the BHJ posterior stays wide (Kan and Zhang 1999).
- Both models report a table of estimates against the true values. Actions reuse the fit (`tp`, `lam`, `lam_point`) instead of re-running `BayesianFM` up to four times. They use the package's own `tp.beta` and `tp.alpha`, so the betas are no longer re-estimated by hand.
- `posterior-density` became "Risk Premium Uncertainty": posterior histograms for the Bayesian model, and estimates with 95% Shanken intervals for the Classical model.
- `mcmc-trace` was **removed** and replaced by a new `weak-factors` action. A trace plot of independent draws shows nothing about convergence. The new action runs a Wald test that every loading on a factor is zero, using `tp.cov_beta`, and reports the Monte Carlo error of the posterior means.
- `pricing-errors`: alphas against the selected estimates, Shanken t-statistics, and a note on the common intercept.
- `posterior-predictive` became "Expected Return Bands": 90% bands from the posterior draws (Bayesian) or the delta method (Classical). They are labelled "given the estimated betas" (finding 3).
- `bayes-vs-classical`: a side-by-side table. The comment no longer claims that Bayesian FM shrinks weak factors. With flat priors it does not; it leaves their posterior wide (finding 2).
- `credible-intervals` became "Interval Estimates": annualised, with the right reading for each paradigm. `significance`: Pr(premium > 0) for the Bayesian model, and Shanken p-values with a weak-factor caveat for the Classical one.
- Distributions.jl was added for the chi-squared and normal p-values. References added: Kan and Zhang (1999), Shanken (1992).

**Out of scope.** The six bfmb notebooks are "Coming soon!" placeholders, and the six wiki pages are three-line stubs. FamaFrenchData.jl stays on the Powered-by line, but no panel code uses it.

## ptp: Point Processes

**Invented calls.** `CoxProcess(...)`, `fit(cox, data, T)` with `.mu_post`, `HawkesProcess(mu, alpha, beta)`, `fit(process, data)`, `NetworkHawkesProcess(...)`, `intensity(process, t, data)`, `cumulative_intensity`, `next_event`, `simulate(...; history)`, `loglikelihood(process, data)`, `weight_matrix(result)` and a `qqplot` from Plots. None of these exist in the three listed packages. `process` was undefined outside the Hawkes branches, so most actions failed for the other models. The Poisson interval was a Wald interval, and the kernel intensity had no edge correction.

**Real API used.** Read from source; each tree hash matches the registry.
- PointProcesses.jl 0.5.0, the latest registered release, has Poisson processes only (Hawkes exists only in the unregistered 0.6/0.7 development line). Used: `History(; times, marks, tmin, tmax)`, `MultivariatePoissonProcess`, `fit(MultivariatePoissonProcess{Float64}, h)`, `ground_intensity`, `integrated_ground_intensity`, `logdensityof`, `rand(pp, tmin, tmax)` (its times are unsorted, so the code sorts them) and `event_times`.
- HawkesProcesses.jl 0.1.4: `fit(events, T, its)` is a Gibbs sampler with latent parents that returns draws of (mu, kappa, beta). The kernel is kappa times an Exponential(1/beta) density, so alpha = kappa beta. Also used: `simulate`, `intensity`, `compensator`, `likelihood` and `simulate_forward`.
- NetworkHawkesProcesses.jl 0.1.0:
  - Used: `ContinuousStandardHawkesProcess`, `ContinuousNetworkHawkesProcess`, `HomogeneousProcess`, `LogGaussianCoxProcess`, `ExponentialImpulseResponse`, `DenseWeightModel`, `BernoulliNetworkModel`, `mcmc!` (`.samples`), `mle!` (`.maximum`), `intensity`, `loglikelihood` and `rand`.
  - Not exported, so called qualified: `GaussianProcess`, `SquaredExponentialKernel`, `OrnsteinUhlenbeckKernel` and `params!`.
  - Data are `(times, nodes, duration)`. The samples are laid out as described in the code comments.
- The packages are imported qualified (`import HawkesProcesses as HP`, `import NetworkHawkesProcesses as NHP`) because their `fit`, `intensity` and `loglikelihood` clash.

**Changes.**
- Every model defines the same objects: `T`, sorted `t_obs`, the fitted intensity `lam(t)` and the compensator `Lam(a, b)`. With simulated data it also defines the true intensity `lam_true(t)`. The actions use only these objects (plus the posterior draws where they exist), so every action now runs for every model or prints why it does not apply.
- Poisson: PointProcesses MLE with an exact Garwood 95% interval. The new input "Rate (lambda)" sets the simulated truth.
- Inhomogeneous: KernelDensity estimate scaled by n, with Diggle's edge correction, and a new "Bandwidth (h)" input. The example has a known sinusoidal truth, simulated by thinning a PointProcesses Poisson process.
- Cox: a log-Gaussian Cox process from NetworkHawkesProcesses.
  - The posterior of the intensity path is sampled by elliptical slice sampling and reported with a 95% band.
  - The package's Cox baseline comes with a self-excitation weight W. Its posterior, which should sit near 0 for Cox data, is reported as a check.
  - The kernel options became Squared Exponential and Ornstein-Uhlenbeck, the two the package provides; the Matern options were removed.
- Hawkes: Gibbs posterior from HawkesProcesses, giving means and 95% intervals for mu, alpha, beta and kappa, printed against the true values.
- Network Hawkes:
  - Gibbs posterior of the links, weights, decays and baselines.
  - Reported: the link probabilities, against the true links when the data are simulated.
  - The plug-in intensity uses the posterior mean of A.*W.
  - New input "Event Nodes".
- A new input "Gibbs Iterations" applies to Cox, Hawkes and Network Hawkes. The first quarter is discarded as burn-in.
- Actions:
  - The time-rescaling KS test and Q-Q plot use the fitted compensator, per node for the network model. The KS output notes that the test is conservative because the model was fitted to the same events.
  - Branching ratio:
    - Hawkes: P(kappa < 1).
    - Network: the posterior spectral radius of A.*W.
    - Cox: the W posterior.
  - The next-event distribution is computed as 1 - exp(-integral of lambda).
  - Forward simulation uses `rand` (Poisson) or `simulate_forward` over posterior draws (Hawkes). The expected count now reports its Monte Carlo error and a 90% predictive interval.
  - "AIC / BIC" became "Poisson vs Hawkes": the PointProcesses MLE against the NetworkHawkesProcesses `mle!`. It explains why no chi-square LR test is given: under Poisson the branching ratio is on its boundary and beta is not identified.
  - Branching structure: the immigrant share and cluster size (Hawkes) and the stationary rates (Network).
  - Network connectivity: heatmaps of P(link) and A.*W.
- KernelDensity.jl added to the Powered-by line. `[requires]` now lists every package used. References added: Garwood (1936), Diggle (1985), Moller, Syversveen and Waagepetersen (1998), Rasmussen (2013), Linderman and Adams (2014), Brown et al. (2002).

**Out of scope.**
- Package limitations:
  - NetworkHawkesProcesses' `loglikelihood` and `mle!` count each event's full offspring mass, ignoring the truncation at T, so they slightly understate the compensator near the end of the window.
  - Its Cox intensity exists only on [0, T], so the Cox and inhomogeneous models give no forecasts. No package offers conditional simulation for the network model.
- The notebooks and wiki pages are placeholders, as before.

## ptps: Point Process Simulation

**Invented calls.** `PoissonProcess(lambda)` with `rand(process, T)`, `simulate_inhomogeneous`, `CoxProcess(kernel; mu)` (built on GaussianProcesses.jl kernels), `HawkesProcess(mu, alpha, beta)`, `NetworkHawkesProcess(mu, W, beta)`, `simulate(process, T; history)` and `intensity(process, t, events)`. None of these exist in the listed packages. `process` was undefined for the inhomogeneous and Cox models, so most actions failed there.

The review's wrong-statistics findings:
- "Count vs Theory" compared every model with the Poisson mean lambda * T.
- The KS test checked every model's gaps against Exp(lambda).
- "Expected Count" integrated the intensity with no future events, so it left out future offspring.
- The Network weight matrix was `rand(N, N) .* 0.3`, which is explosive for N > 3.
- The HawkesProcesses link pointed to the wrong repository (dmillot instead of dm13450).

**Real API used.** These are the same package versions as ptp, read from source.
- PointProcesses.jl 0.5.0: `MultivariatePoissonProcess`, `rand(pp, tmin, tmax)` (Ogata; times unsorted) and `event_times` / `event_marks`.
- HawkesProcesses.jl 0.1.4:
  - `simulate(mu, kappa, kern, T)`: a cluster simulation with sorted output.
  - `poisson_simulation(rate::Function, T, lambda_max)`: Lewis-Shedler thinning. It is not exported, so it is called qualified, and it needs a vectorised rate.
  - `intensity`, `compensator` and `simulate_forward`.
- NetworkHawkesProcesses.jl 0.1.0:
  - `LogGaussianCoxProcess(gp, m, T, n, 1)` draws a path on a grid with linear interpolation; `rand(cox, 1, T)` gives events given the path.
  - `ContinuousStandardHawkesProcess(HomogeneousProcess, ExponentialImpulseResponse, DenseWeightModel)` with `rand(process, T)` simulates the clusters. The impulse is W times an Exponential density, so W[m, n] is the expected number of direct offspring.
  - Also used: `intensity`, `isstable`, and the unexported `GaussianProcess` / `SquaredExponentialKernel` / `OrnsteinUhlenbeckKernel`.

**Changes.**
- Every model defines the same objects:
  - `T` and sorted `events`;
  - the true intensity `lam(t)` and compensator `Lam(a, b)`;
  - the exact `EN` = E[N(T)] for that model;
  - `sim()` for a fresh realisation.
- Exact expected counts:
  - Poisson: lambda T.
  - Inhomogeneous: the integral of lambda(t).
  - Cox: T exp(mu0 + sigma2/2) over paths (each interpolated value is a lognormal mean), and the integral of the path given the drawn path.
  - Hawkes: the transient-corrected mean from no history.
  - Network: the matrix-exponential solution of the mean-intensity ODE.
- Inhomogeneous: the code checks that lambda(t) is non-negative and at most lambda_max on a fine grid, because a bound below the peak simulates the wrong process.
- Hawkes and Network: they stop with an error when explosive. For Network, W is random and rescaled to a new "Spectral Radius (rho)" input, default 0.6.
- Cox: the kernel options became Squared Exponential and Ornstein-Uhlenbeck (the package's two); the Matern options were removed. The GaussianProcesses.jl dependency was dropped.
- Actions:
  - "Count vs Theory" uses the model's own E[N(T)]. It gives a Poisson z-score only where Var = mean, and points to Multiple Seeds for the overdispersed models.
  - The KS test became a time-rescaling test with the true compensator, per node for Network. The parameters are known, so it has its nominal level.
  - "Extend Horizon" uses the package simulators: Poisson `rand`, thinning, and `simulate_forward` for Hawkes. Cox and Network print why there is no conditional simulator.
  - "Expected Count" gives E[N(T, T + h) | history] including offspring: a closed form for Hawkes, checked by Monte Carlo with `simulate_forward`, and the matrix form for Network.
  - "Multiple Seeds" reports the mean with its Monte Carlo error against theory, plus the variance-to-mean ratio.
  - "Superposition" uses a two-mark `MultivariatePoissonProcess` and runs an exact KS test of the merged gaps against Exp(1.5 lambda).
  - "Branching Structure" and "Mean Event Rate" work per model; Network gets stationary rates (I - transpose(W)) \ mu.

## mlmc: Multilevel Monte Carlo

**Invented calls.**
- `MLMC()`, `MLQMC()` and `GaussianSampler`.
- The keywords `NumberOfLevels` and `MSE`, and `run(estimator)` with no tolerance.

The review (batch 6) also found:
- Finding 2: the estimand was degenerate. The default `sin(2^-l x)` with X ~ N(0, 1) has mean 0 on every level, and the sample function returned Q itself rather than the pair (Q_l - Q_(l-1), Q_l), so every rate and the complexity check were measured on noise.
- Finding 3: the cost forecast assumed the tol^-2 regime without saying so, and the MSE decomposition was obtained by subtraction.

**Real API used.** MultilevelEstimators.jl 0.1.5 (PieterjanRobbe, MIT, unregistered, already in `UNREGISTERED_PACKAGE_URLS`), read from source.
- `Estimator(ML() | SL(), MC() | QMC(), sample_function, distributions; max_index_set_param, min_index_set_param, nb_of_uncertainties, nb_of_shifts, cost_model, save, verbose)`. The sample function takes `(level::Level, x)` and returns `(dQ, Q)`.
- `run(estimator, tol)` returns a `History`. `h[key]` reads the last run: `:mean`, `:rmse`, `:mse`, `:varest`, `:bias`, `:tol`, `:current_index_set` and `:nb_of_samples`, plus the per-level Dicts `:E`, `:V`, `:dE`, `:dV`, `:T` and `:W`.
- The rates are stored under the Greek keys alpha, beta and gamma. The panel reads them as `Symbol("α")` and so on, so the source stays ASCII.
- `Normal()` is the package's own distribution type, so Distributions.jl is not loaded: it would clash with that name.

**Changes.**
- The user-supplied sample function body and dimension inputs were replaced by two built-in problems with exact answers, as the review proposed:
  - **Random Integral.** Q = integral over [0, 1] of exp(X t) dt, with X ~ N(0, 1). Level l uses the midpoint rule with 2^l points. The exact mean is the integral over [0, 1] of exp(t^2 / 2) dt = sqrt(pi / 2) erfi(1 / sqrt 2) = 1.194958, computed with SpecialFunctions.
  - **GBM Call Option.** A discounted European call. Level l uses Euler-Maruyama with 2^l steps, and the coarse path sums pairs of the fine Brownian increments. The exact mean is the Black-Scholes price. The five option inputs are shown for this problem only.
- In both problems the sample function returns (Q_l - Q_(l-1), Q_l) from the same random input (finding 2).
- **Theoretical rates:**
  - Random Integral: alpha = 2, beta = 4, gamma = 1. The review gave beta = 2, but the midpoint correction is O(h^2) for every X, so its variance is O(h^4).
  - GBM Call Option: alpha = beta = gamma = 1, the Giles (2008) case.
- **Cost model.** `cost_model = level -> 2^l` (grid points or time steps), so costs and gamma are deterministic and not distorted by timing noise. Measured times are shown separately in Cost per Level. Under QMC the package counts samples per shift, so QMC costs are multiplied by the number of shifts.
- **Inputs.** Relative Tolerance replaces Target MSE: the target RMSE is the relative tolerance times the exact value. Max Level replaces Levels. New inputs: n Shifts (MLQMC only) and Seed (the package uses the global RNG).
- **Estimator options.** `save = false` stops the package from writing .jld2 files into the working directory (its default is true). `verbose = false` replaces the package's printout with a short summary: estimate against the exact value, error against the estimated RMSE, levels used, samples and total cost.
- **Actions** read the main run's `History`. Only Cost vs Tolerance, Multilevel vs Single Level, Max Level Sweep and Complexity Check rerun, through `ml_run` / `sl_run` helpers that use the same sample function. The single-level comparison is `SL()` on the same finest level.
  - Cost Forecast (finding 3) states the regime from Giles (2015), Theorem 1, using the measured alpha, beta and gamma: tol^-2, tol^-2 log(tol)^2 or tol^-(2 + (gamma - beta) / alpha).
  - MSE Decomposition (finding 3) prints the package's own `varest` and `bias` and the actual squared error.
  - Confidence Interval reports the bias separately from the sampling interval.
  - Max Level Sweep sets `min_index_set_param = min(2, maxlevel)`, because the package default of 2 errors when the maximum level is 1.
- **References.** The MultilevelEstimators.jl reference cited arXiv 1910.07711, which is an unrelated finite-element paper. It now points to the GitHub repository (2018, from the licence). The Heinrich (1998) and Kuo et al. (2017) DOIs were checked against Crossref.

**Package replaced.** The rewrite on SequentialMonteCarlo plus SMCExamples was abandoned. Its RNG dependency RNGPool 2.0.0 sizes its pool with `Threads.nthreads()` and indexes it by `Threads.threadid()` under `@inbounds`. On Julia 1.12 the main thread is interactive thread 1 and `Threads.@threads` runs on thread 2, so `RNGPool.__init__` writes past the end of a length-1 pool. `using RNGPool` aborts the process with signal 6 in a default Julia 1.12 session. This was found with a one-line load test in a scratch environment; no panel code was run. SequentialMonteCarlo, SMCExamples and RNGPool have had no commits since 2021. With the user's agreement, the panel was moved to LowLevelParticleFilters, which is registered, actively maintained and already used by ssm.

**Real API used.** LowLevelParticleFilters 3.33.1, read from source:
- `ParticleFilter(N, dynamics, measurement, df, dg, d0; resample_threshold, rng)` is a bootstrap filter with additive noise.
  - `dynamics(x, u, p, t)` and `measurement(x, u, p, t)` take and return state vectors, and `df`, `dg` and `d0` are Distributions `MvNormal`s.
  - `predict!` resamples (systematic, with the global `rand()`) when `effective_particles < resample_threshold * N`, or at every step when the threshold is 1.
- `simulate(pf, u; sample_initial = true)` returns true states, inputs and observations. Without `sample_initial`, x[1] is the mean of `d0`.
- `forward_trajectory(pf, u, y; post_correct_cb, post_predict_cb)` returns a `ParticleFilteringSolution`:
  - `x` and `we` are N x T: the particles and normalised weights of x(t|t), before resampling.
  - `ll` is the log-likelihood estimate. Each increment is log sum_i W_i p(y | x_i), so its exponential is unbiased.
  - The callbacks receive `lli` per step, and `pf.state.j` holds the ancestor indices after each `predict!`.
- `KalmanFilter(A, B, C, 0, R1, R2, d0)`. Its `forward_trajectory` gives `xt`, `Rt` and `ll` with the same convention (x[1] ~ d0, correct then predict), and `post_correct_cb(kf, p, ret)` exposes `ret.ll`. `smooth(ksol)` is the RTS smoother (`xT`, `RT`).
- `smooth(pf, M, u, y)` is forward filtering, backward simulation and returns an M x T array of trajectories. `smoothed_trajs` reshapes it to nx x M x T.
- Also used: `loglik(pf, u, y)` and `effective_particles(we) = 1 / sum(we .^ 2)`.

**Changes.** The panel follows the review's proposal (batch 8, finding 3):
- The model is linear-Gaussian, x[t + 1] = a x[t] + w and y[t] = c x[t] + e, with x[1] ~ N(m0, v0). Data are simulated from it, so every particle result has an exact Kalman counterpart.
- Inputs: a, c, q, r, m0 and v0 (defaults 0.9, 1.2, 0.6, 1.5, 1, 2, as in the SMCExamples default), N, T, Resampling Threshold (0.5), Smoother Trajectories M (100) and Seed. The free-text `lG body` input was removed, because a free potential has no exact reference.

  - Diagnose: ESS per Step. Log-Likelihood Trajectory, the cumulative PF and Kalman values and the per-step differences. Resampling and Path Degeneracy, which traces the final particles back through the recorded ancestors and shows why the smoother simulates backwards.

## ssm: State-Space Inference Methods (rbf)

**Real API used.** LowLevelParticleFilters 3.33.1, read from `src/rbpf.jl`, `test/test_rbpf.jl`, `test/test_mukf.jl` and `docs/src/rbpf_example.md`:
- `RBPF(N, kf, dynamics, nl_measurement_model, R1n, d0n; An, nu, names)` is the marginalised particle filter of Schon, Gustafsson and Nordlund (2005), their model 2:
  - xn(t+1) = f_n(xn) + An xl + wn;
  - xl(t+1) = A xl + B u + wl;
  - y = g(xn) + C xl + e.

  `An` and `names` are required keywords. The filter is marked experimental in its docstring.
- `kf` is a `KalmanFilter(A, B, C, 0, R1l, R2, d0l; ny, nu)` for the linear substate. Each particle carries its own Kalman mean `xl` and covariance `R`.
- `RBMeasurementModel(g, R2, ny)` holds g and the measurement noise. Matrices are converted to `SimpleMvNormal`. Since `An` is not zero, `R1n` must be Gaussian.
- Particles are `RBParticle`s, which index like `[xn; xl]` and expose the fields `xn`, `xl` and `R`. `forward_trajectory`, `loglik`, `simulate`, `mean_trajectory` and the plot recipe work as for `ParticleFilter`.
- Two particle helpers do not apply:
  - `weighted_cov` reinterprets each particle as raw Float64s, and an `RBParticle` also stores `R`.
  - The forward-filter backward-simulation `smooth(pf, M, u, y)` calls `pf.dynamics` (which maps `xn` only) on the whole particle and scores it with the joint dynamics density.

  The package has no RBPF smoother.

**Changes.**
- The `rbf` branch builds a mixed model from the panel inputs:
  - f_n from the dynamics input (default `atan.(xn)`) and g from a new measurement input (default `fill(0.1 * sum(abs2, xn), ny)`);
  - `An` and `C` as rectangular identities, and a random-walk `A`;
  - noise from the shared Q and R scale inputs, which now also apply to `rbf` and replace the hard-coded 0.1s;

  It returns the log-likelihood and the weighted mean of [xn; xl] at time T.

  - State Uncertainty: the variance of the Gaussian mixture. This is the weighted spread of the particle means (`weighted_cov` on `SVector` copies), plus, for xl, the weighted mean of the particle Kalman covariances.
  - Particle Count: rebuilds an `RBPF` per N instead of a `ParticleFilter`.

## lda: Latent Dirichlet Allocation

**Problem.** The panel declared TopicModels.jl and called `LDA`, `fLDA`, `train!`, `showtopics` and `topicdist`.
- That API belongs to TopicModelsVB.jl 1.5.2, not TopicModels.jl. Its registry compat (Distributions 0.23, SpecialFunctions 0.8 to 0.10, OpenCL 0.8) cannot resolve in a current environment.
- slycoder TopicModels.jl was last committed in 2020 and has a different API.

**Package.** TextAnalysis 0.8.5 `lda(dtm, ntopics, iterations, alpha, beta)` fits by collapsed Gibbs sampling and returns `(phi, theta)`: k x V p(word | topic) and k x N p(topic | document). Read from source:
- **The priors are swapped relative to the docstring.** The 4th argument smooths the topic-word counts and the 5th the document-topic counts. The panel passes the topic-word prior b 4th and the document-topic prior a 5th, with a comment.
- phi and theta are the unsmoothed counts of the final sweep (one sample, not a posterior mean). A document with no tokens gets a NaN column in theta; the actions replace NaN with 0 where it matters.
- It samples with the global RNG, so `fit_lda` seeds before each fit.

**Changes.**
- One model, `lda`. With the user agreement, `flda` (Focused LDA) was removed: its model, code branch, bullet, notebook and wiki entries, the stub files `notebooks/lda/tutorial-02-flda.ipynb` and `wiki/lda/flda.md` (both empty or "Coming soon!"), the IBP compound Dirichlet reference, and the command `NLP_FLDA_ID` (registered but in no menu). No Julia package implements fLDA.
- Main code: TextAnalysis cleaning, `DocumentTermMatrix`, `lda`, the top 10 words per topic, and two helpers the actions share:
  - `umass`: UMass coherence from document co-occurrence (Mimno et al. 2011);
  - `heldout_perplexity`: document completion (Wallach et al. 2009). It holds out a share of each document tokens, refits, scores the held-out tokens with posterior-mean phi and theta rebuilt from the counts, and reports an add-one unigram baseline.
- Inputs added: document-topic prior alpha (0.1), topic-word prior beta (0.01), held-out share, seed, topic to inspect, new document. The `iters` tooltip said "variational EM"; it now says Gibbs sweeps.
- Actions:
  - Visualise: top-word bars for up to six topics; theta heatmap.
  - Diagnose: held-out perplexity against the unigram baseline; UMass coherence per topic.
  - Predict: `lda` has no fold-in, so Infer Topics refits with the new document appended and labels the re-estimated topics by their own top words; Top Documents ranks documents by theta for the chosen topic.
  - Compare: Compare k Topics gives held-out perplexity and mean coherence for k = 2, 5, 10, 20. LDA vs LSA replaces LDA vs fLDA and compares mean UMass coherence with the dimensions of `lsa(dtm)`, sign-oriented by their largest loading (the full LSA lives in its own panel).
