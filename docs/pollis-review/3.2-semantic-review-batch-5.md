# 3.2 Semantic review of the code examples, batch 5

Task 3.2 of the Pollis Polish Roadmap. Batch 5 is files 97 to 120 of `LC_ALL=C ls src/vs/workbench/contrib/model/browser/webviews/*.toml`, from `ido` to `mcat`. All 24 panels were reviewed.

The code was read as `node build/pollis/extractCodeExamples.ts` renders it (`.build/code-examples/<id>/<model>.jl`), covering the default code of every model and every Next Steps action, with each input at its default. No Julia was run; task 3.4 runs the code. Wikis and notebooks are out of scope. Verdicts, finding ratings and the "fixed" rule follow the batch 1 report (`3.2-semantic-review-batch-1.md`). A panel with a finding rated wrong is rated at least questionable, even when that finding is fixed here.

Items already tracked elsewhere are not repeated: postfix transposes, `bert` token attribution, `rl` Zygote, the `kgds`/`diff` mentions and `rxinfer`'s `gaussian_model`.

## Cross-cutting findings

- **V1. Package APIs that probably do not exist.** In several panels the whole panel is written against functions I cannot match to the package's documented API. None of this can be fixed locally; task 3.4 will show it at once.
  - `lda`: `LDA`, `fLDA`, `train!`, `topicdist`, `perplexity`, `coherence`, `infer` and `showtopics` are not in TopicModels.jl.
  - `llmTa`: `aitag`, `aiclassify`, `aisummarize`, `aiask` and `find_tags` on an index are not in LLMTextAnalysis.jl.
  - `lrm`: I know of no registered Julia package called PerformanceAnalytics.jl.
  - `kgm`: the default code is pseudo-code.

  The pattern is the same each time: plausible R- or Python-style names, with no call a user could run.
- **V2. In-sample evaluation presented as a test.**
  - `lrm`'s VaR backtest counted breaches of a VaR fitted to the same returns, so the breach rate was alpha by construction (fixed; the same kind of tautology as W2 in batch 4).
  - `mc` fits and scores its calibrators on the same validation set.
  - `lca`'s choose-k uses in-sample reconstruction error, which always falls as k grows.
  - `lda` calls its perplexity "held-out" but has no split.
- **V3. Raw template substitution.** `llmTa` put `{{llmmodel}}` into code unquoted, so `model=gpt-4o-mini` parsed as a subtraction (fixed). This is the same class of problem as W3 in batch 4.
- **V4. Options that the actions ignore.**
  - `lm`'s robust-inference toggle changes only the default table: the coefficient plot, coefficient table and F-test stay classical.
  - `lmm`'s Hausman test uses classical covariances while the panel offers clustered inference.
  - `jdp`, `lda`, `lrm` and `llmTa` actions ignore the selected model.
- **V5. Non-ASCII in code.**
  - `kgm` uses the `÷` operator and box-drawing characters in code (left as is: the panel's other fixes were already committed, and task 3.3 can sweep it with the transposes).
  - `jdp` and `kgm` have en and em dashes in comments.
  - `lm` and `lmm` print `R²` in strings.
- **V6. Timing first calls.** `lp` and `mbm` solver comparisons, and `kgm`'s ONNX-versus-Python comparison, time the first call, which is mostly compilation.

## Panel reviews

### ido: Infinite-Dimensional Optimisation

**Sound, rich.** A minimum-energy double integrator with bounds. It includes ODE residuals, mesh refinement, open-loop RK4 re-simulation, collocation compared with finite differences, costates as duals (the weights caveat is stated) and initial-state sensitivity compared with the duals.

1. **Questionable.** Add the analytic check. Rest-to-rest over distance 1 costs 12/T^3, with u linear in t and max |u| = 6/T^2. With umax = 5, the horizon sweep is therefore infeasible below T = sqrt(6/5), about 1.1. The action should say that its NaNs there mean infeasibility, not solver failure.

### integ: Integration

**Sound, rich.** Covers data, definite and multiple integrals. Convergence orders (2, 4, spectral) are shown. Richardson extrapolation equals Simpson's rule for equal spacing, which is correct. Examples include the present value of a flow and marginal-to-total cost, with cross-checks by a cubic fit, a symbolic antiderivative and Fubini, and a Monte Carlo standard error. No findings.

### jdp: Jump-Diffusion Processes

**Questionable, thin.**

1. **Wrong, fixed (`d83d9af0`). Action `jump-count`.** Jumps were counted as X(T) - X(0) with the Brownian term still on, so diffusion noise was counted as jumps. Drift and diffusion are now zero, and a comment says that a single path gives a Poisson count around lambda T.
2. **Questionable.** Additive jumps (`rand() - 0.5`, Uniform(-0.2, 0.2), Normal(-0.1, 0.05)) on a geometric diffusion (g = 0.2 X) cause two problems: the price can go negative, and jump sizes do not scale with the level.
3. **Questionable.** The "Merton-style" model is not Merton's. Merton uses multiplicative log-normal jumps, X to X e^J, with a compensated drift.
4. **Questionable. Action `ensemble-moments`.** The description promises the variance, but the action prints only the mean and gives no theoretical value (exp(0.05 T) for the mean here).
5. **Questionable. Action `jump-dist`.** It recovers the N(0, 0.05) it simulated, which is circular. Its `SDEProblem(x -> ...)` also has the wrong signature (for task 3.4).
6. **Questionable.** The actions ignore the selected model and define their own jumps (V4).

**Proposal (thin).** Make the jumps multiplicative, X to X exp(J), with J ~ N(mu_J, sigma_J), and compensate the drift by lambda (E[e^J] - 1). The panel is then Merton's model and prices stay positive. The actions should reuse the selected model's jump law and add three things:
- the closed-form mean and variance of log X(T) against the ensemble;
- a jump-size estimate from simulated returns (large increments above a threshold), compared with the true law;
- a Merton option price by the Poisson-weighted Black-Scholes series, compared with Monte Carlo.

Also show the dataset's licence and version from the metadata endpoint, since those decide whether results can be published.

### kgm: Kaggle Models

**Questionable, thin.**

1. **Wrong, fixed (`1531f19c`). Action `prediction-probs`.** It plotted logits as probabilities; softmax is now applied first.
2. **Wrong, fixed (same commit). Action `batch-inference`.** `model.(stack(chunk))` broadcast the model over array elements; it now makes one forward pass on the stacked batch.
3. **Questionable.** The default code is pseudo-code: `log_mel_spectrogram`, `preprocess`, `tokenize`, `decode` and `IMAGENET_LABELS` are undefined (V1). For the NLP model, the argmax of one forward pass is not generation, and Whisper is an encoder-decoder, not a single forward call.
4. **Questionable. Action `julia-onnx-vs-python`.** The two sides are not comparable, in outputs or in times:

### lasso: Penalised & Projection Regression

**Sound, rich.** Includes the regularisation path, bootstrap selection stability, CV RMSE against OLS on the same folds, AICc, BIC, CV-min and CV-1SE, and standardised importance. Lasso.jl's Greek keywords are written with `Symbol(Char(...))`, as policy requires.

1. **Questionable.** The default formula `y ~ x1 + x2` has two predictors, where selection and shrinkage have nothing to do. The method only matters with many correlated predictors.
2. **Questionable.** On the `plsr` toggle every action stops with `error()`, so PLS has no Next Steps. The PLS model itself is correct: W (P'W)^-1 Q'. `df` is undefined.

### lca: Latent Component Analysis

**Sound, adequate.** FA, kernel PCA and PCA, with scores, scree, reconstruction error, projection of new data, neighbours, loadings and biplots.

1. **Questionable. Action `choose-k`.** It uses in-sample reconstruction error, which falls monotonically with k, so it cannot choose k on its own. Use parallel analysis or held-out error (V2).
2. **Questionable.** For kernel PCA, "explained" is a share of variance in the kernel feature space, not of the data's variance; say so.

### lda: Latent Dirichlet Allocation

**Wrong, thin.**

1. **Wrong, not local.** The code is not written against TopicModels.jl's API. slycoder/TopicModels.jl provides `Corpus`/`readDocs`, `Model(alpha, beta, k, corpus)`, `trainModel` and `topTopicWords`, using collapsed Gibbs sampling. It has no `LDA`, `fLDA`, `train!`, `topicdist`, `perplexity`, `coherence`, `infer` or `showtopics`. TextAnalysis.jl has `lda(dtm, k, iterations, alpha, beta)`, which returns (phi, theta) and also uses Gibbs sampling. As written, none of the code runs (V1).
2. **Wrong.** "Variational EM" is wrong for both packages, and "focused LDA" is not a standard model.
3. **Wrong.** The same call, `topicdist(model)`, is labelled topic-word (k x V) in the default code and document-topic (N x k) in the actions.
4. **Questionable.** `perplexity(model)` is described as held-out, but there is no split (V2).
5. **Questionable.** The actions always fit LDA, whatever model is selected. `corpus`, `new_doc_dtm` and `topic_id` are undefined. The bundled notebooks are "Coming soon" stubs.

**Proposal (thin).** Rewrite against `TextAnalysis.lda`, which returns topic-word phi and document-topic theta. Hold out 10% of each document's tokens (document completion) for perplexity, and choose k with it. Measure coherence as UMass or NPMI on the top words, computed by hand from the DTM. Show top words, a document-topic heatmap and topic prevalence. Drop fLDA unless a real implementation is named.

### lm: Linear Regression

**Questionable, rich.** OLS and WLS with standard, HC0 to HC3, HAC, clustered and Driscoll-Kraay inference. Actions include fitted against observed, a coefficient plot, residuals, Q-Q, leverage and Cook's distance, confidence against prediction intervals, a nested F-test, adjusted R2 with AIC and BIC, and standardised coefficients.

1. **Wrong, fixed (`c7a2e524`). Action `f-test`.** Under WLS, the restricted model was fitted without weights, so the two residual sums of squares were on different scales. The restricted model now uses the same weights.
2. **Questionable.** The inference toggle affects only the default table. The coefficient plot, coefficient table and F-test stay classical, so under heteroskedasticity they contradict the robust table printed just above (V4). They should use `V`.
3. **Questionable.** Under WLS, the residual plots should use sqrt(w) .* r, and the prediction interval assumes a new observation has weight 1. `coeftable(model, V)` and the `DriscollKraay` constructor need checking against CovarianceMatrices.jl (task 3.4).

### lmar: Linear Models with Autocorrelation

**Sound, rich.** Regression with AR(1) errors by four estimators. It includes Durbin-Watson and Breusch-Godfrey evidence, innovation checks, and one-step fit against regression-only fit. Forecasts use the correct h-step variance, s2 sum rho^(2j). It also compares OLS and GLS standard errors, compares the estimators, and gives a CI for rho, the half-life and the effective n = n(1 - r)/(1 + r).

1. **Questionable. Action `forecast`.** The "future regressors" are the last five in-sample rows, and the forecast starts from `e[end]`, so step 1 forecasts a row the model has already fitted. Say to replace `Xn` with genuinely new rows.
2. **Questionable. Action `serial-tests`.** The "reading" picks a direction from DW < 2 whatever the p-value printed next to it.

### lmhar: Linear Models with Heteroskedasticity + AR(1)

**Questionable, thin.**

1. **Wrong, fixed (`a1931db8`).** The OLS baseline `lm(X, y)` had no intercept, while HARE adds one. The Durbin-Watson test, residual diagnostics and OLS comparison therefore described a regression through the origin.
2. **Wrong, fixed (same commit).** `DurbinWatsonTest(resid)` lacked the design matrix.
3. **Wrong, fixed (same commit).** `harvey_test(y, X, X)` contradicted the `(X, y)` order used in the `hare` and `lmar` panels.
4. **Wrong, fixed (same commit).** The residual diagnostics drew two plots and showed only the second.
5. **Questionable.** "Joint two-step: simultaneous MLE" contradicts itself: either the fit is two-step or it is joint MLE. `X_new` is undefined.

**Proposal (thin).** Mirror `lmar`, which is rich:
- innovation checks after the combined correction: Ljung-Box on the innovations, and Harvey on the standardised innovations;
- forecasts with variance from the fitted variance function;
- a comparison of OLS, AR(1)-only, heteroskedasticity-only and combined standard errors on the same data;
- an estimator comparison between sequential and joint fits.

The two models currently share identical actions apart from the estimator call.

### lmm: Linear Mixed-Effects Models

**Sound, rich.** A mixed model, entity and two-way fixed effects, and IV, with robust, clustered and two-way clustered covariance. Actions include:
- a caterpillar plot with `condVar`, a singular-fit check and the Kleibergen-Paap first-stage F;
- population-level against conditional fit;
- hold-out with `new_re_levels=:population`;
- a likelihood-ratio test against OLS and a Hausman test of random against fixed effects (the correct form: FE covariance minus RE covariance);
- the ICC and within R2.

1. **Questionable. Action `pooled`.** The LRT of the random intercept tests a variance on its boundary, so the chi-square(1) p-value is conservative by about a factor of 2. Halve it or use a parametric bootstrap, and say so.
2. **Questionable. Action `hausman`.** It uses classical covariances, which are invalid under the clustered inference the panel offers (V4).
3. **Questionable. Action `group-effects`.** It takes `unique()` of the per-row fixed-effect values, which merges groups whose estimates coincide. Group by the id instead.

### lp: Linear Programming

**Sound, rich.** LP and MILP in JuMP with HiGHS on the same data. Actions include the feasible region with integer points, slack and binding constraints, `primal_feasibility_report`, `lp_sensitivity_report` ranges, and a parametric sweep (piecewise linear for LP, steps for MILP). The integrality gap comes from `relax_integrality`. Shadow prices and reduced costs for the MILP use `fix_discrete_variables`, with the "valid only locally" caveat stated.

1. **Questionable. Action `solver-compare`.** It times the first solve of each solver, which is mostly compilation (V6).

### lqr: Linear Optimal Control

**Sound, rich.** Discrete LQR with full state, and LQG with a Kalman predictor under certainty equivalence. Actions include controllability and observability ranks, closed-loop and estimator poles, the cost-to-go x0'P x0 from `ared` against simulation, an R-weight trade-off curve, relative gains, and margins at the plant input.

1. **Questionable. Action `robustness`.** The "generous margins" promise (infinite gain margin, 60 degrees of phase) is the continuous-time LQR result. Discrete-time LQR guarantees less, depending on R and Ts.
2. **Questionable. Action `cost-to-go` for LQG.** x0'P x0 is not the predicted cost. The simulated cost adds estimation error (x_hat starts at 0) and process noise, so it will exceed that figure; say so.

### lrm: Loss Risk Measures

**Questionable, adequate.** Drawdown, downside, ES and VaR families. Actions include a wealth index, a tail histogram, moments, rolling VaR, horizon VaR by the square-root rule, and historical against normal VaR across levels. The ES/VaR ratio of 1.25 for normal returns at 5% is right.

1. **Wrong, fixed (`bf239c11`). Action `var-backtest`.** It counted breaches of a historical VaR fitted to the same returns, so the violation rate was alpha by construction (V2). It now backtests rolling one-step-ahead forecasts and adds an exact binomial test of coverage.
2. **Questionable. Action `es-decomposition`.** "CVaR Decomposition" decomposes nothing: it prints the tail mean of a single series. Rename it, or compute component ES for a portfolio.
3. **Questionable.** The PerformanceAnalytics.jl API (R-style camelCase names) could not be verified, and I know of no registered Julia package by that name (V1). The square-root-of-time rule assumes iid returns, which is not stated. The actions ignore the model. `returns` is undefined.

### lsa: Latent Semantic Analysis

**Wrong, adequate.**

1. **Wrong, fixed (`eaa090cb`). Actions `doc-similarity` and `query-docs`.** Cosine similarity was computed on rows of U_k, which weights every latent dimension equally. LSA document vectors are U_k S_k, which the `doc-topics` action already uses.
2. **Wrong, fixed (same commit). Action `fold-in`.** Four problems:
   - it used `F` and `dtm` without defining them;
   - it called `dtm_row`, which TextAnalysis does not have;
   - it projected raw term counts onto the SVD of the tf-idf matrix;
   - it skipped the corpus's text cleaning.

   It now builds the space, applies the corpus idf and the same cleaning, and computes S_k^-1 transpose(V_k) v. The two postfix transposes on the rewritten lines became `transpose()` calls, so the anomaly total drops from 98 to 96.
3. **Questionable. Action `compare-tfidf`.** It compares absolute sums of squared singular values of two matrices on different scales, which means nothing. Compare the shares S_k^2 / sum S^2 instead. "Variance explained" is the energy of an uncentred matrix.
4. **Questionable.** A full dense SVD of the DTM does not scale (use a truncated sparse SVD). k = 50 exceeds the number of documents in small corpora. `corpus`, `query_idx` and `new_text` are undefined.

### madp: Multi-Agent Decision Processes

**Sound, rich.** Dec-Tiger, with the Nair et al. (2003) setup checked:
- rewards -2, +20, -50, +9, -101 and -100;
- listening accuracy 0.85;
- reset and uniform observations after a door is opened.

It is solved by exact policy-tree evaluation, exact best responses and JESP with restarts. There is an equilibrium check, simulation against the exact value, and centralised-POMDP and fully observed bounds. Exhaustive search is compared with JESP at horizon 2 or less, and there are baselines.

The zero-sum stochastic game is solved by Shapley iteration with LP matrix games. Actions show exploitability per state, sensitivity to the discount, pure maximin and minimax against the mixed value, myopic against equilibrium play by exact policy evaluation, and the split between immediate payoff and continuation.

No findings. The action ids `price-of-anarchy`, `zerosum-vs-general` and `cooperative-vs-competitive` do not match their labels, but users never see the ids.

### manifold: Manifold Learning

**Sound, rich.** Diffusion maps are written out: alpha = 1 density normalisation, symmetric conjugate, right eigenvectors and lambda^t scaling are all correct. Isomap and LLE come from ManifoldLearning.jl. Actions include:
- trustworthiness, implemented exactly (Venna-Kaski normalisation);
- the k-NN graph drawn on the embedding to show tears and short circuits;
- a Shepard diagram and the choice of k or sigma;
- LLE-style placement of new data;
- a PCA baseline and feature correlations.

1. **Questionable. Actions `residual-variance` and `vs-pca`.** Residual variance is computed against Euclidean input distances. Tenenbaum's residual variance for Isomap uses graph geodesic distances. Against Euclidean distances, a correct unrolling of a curved manifold scores badly, so the comparison is biased toward PCA. Use k-NN graph shortest paths, or say that this measure rewards linear embeddings. `X_train` and `X_new` are undefined.

### marl: Multi-Agent Reinforcement Learning

**Sound, rich.** Self-contained tic-tac-toe self-play: TD(0) on mover-normalised afterstates, with both terminal updates handled. A memoised negamax oracle provides:
- evaluation against random and perfect players from both seats;
- opening values;
- the perfect replies.

The cooperative rendezvous task compares IQL, VDN (shared TD error on Q_tot = sum Q_i) and a central joint-action learner against the optimal start value -sum gamma^k for k = 0 to n-2, which checks out. Further actions test coordination across seeds, ablate with a random agent, sweep exploration and draw per-cell action maps.

1. **Questionable.** With 3 or 4 agents on an even grid, no cell is within n-1 steps of all four corners. The "lower bound" n-1 is then still a valid bound but not attainable.

### mbm: Model-Based Methods

**Questionable, rich.** PRIMA (NEWUOA, UOBYQA, BOBYQA, LINCOA, COBYLA) and NLopt (PRAXIS, Sbplx) on Rosenbrock, with every evaluation recorded. Actions include:
- a convergence curve and the surface with the best-so-far path;
- a query scatter, multi-start runs, bound slack and a warm start;
- method and implementation comparisons, and a budget sweep;
- constraint activity and finite-difference Hessian conditioning.

1. **Wrong, fixed (`e1316ff2`). Action `convergence-check`.** It reported the raw gradient norm, which is not zero at a constrained minimum. With the default constraints (sum x^2 <= 2 for COBYLA, sum x <= 2 for LINCOA), the optimum (1, 1, 1, 1) is cut off, so a correct run looked unconverged. The action now also reports the gradient left after removing the normals of active bounds and constraints.
2. **Questionable. Action `method-comparison`.** It times the first call of each method (V6).
3. **Questionable. Action `scaling-check`.** At a constrained minimum, the Hessian that matters is the reduced Hessian of the Lagrangian.

### mc: Model Calibration

**Wrong, thin.**

1. **Wrong, fixed (`a617ce2f`). Model `isotonic`.** The PAV loop merged only adjacent pairs in a single forward pass, so its output was not monotone in general. It also returned values in score order, while every action compared them with labels in the original order. It is now a standard block-merging PAV that returns values in the original order.
2. **Wrong, fixed (same commit). Actions `ece` and `brier` for `temperature`.** The baselines treated logits as probabilities; they now use sigmoid(logits).
3. **Wrong, fixed (same commit). Action `reliability`.** It called `mean` without `Statistics`, dropped probabilities equal to 1 and drew empty bins as points at zero.
4. **Questionable.** Calibrators are fitted and evaluated on the same validation set, which flatters isotonic regression most (V2). PAV ignores ties in scores. Nothing shows how to apply the fitted map to new scores.
5. **Questionable.** The `calibrationerror(estimator, p, y)` form belongs to older CalibrationErrors.jl. Newer versions call `ECE(...)(p, y)` and expect probability vectors for binary data (task 3.4).

**Proposal (thin).** Split the validation set into calibration and evaluation halves, or cross-fit. Fit all three calibrators on the first half and report Brier score, log loss and ECE on the second, with bootstrap intervals. Add:
- a reliability diagram overlaying raw and calibrated predictions, with bin counts;
- a Predict action that applies each fitted map to new scores (for isotonic, step interpolation);
- a Compare action that shows isotonic overfitting as the calibration set shrinks.

### mcat: MeshCat 3D Visualisation

**Questionable, thin.** A viewer utility (scenes, frames, URDF, animation) with nothing statistical to get wrong.

1. **Wrong, fixed (`dc214cb0`). Action `introspect`.** It promised to list the scene tree but called `delete!(vis)`, which cleared the whole scene, and then deleted a subtree that no longer existed. It is now labelled "Scene Cleanup", removes only the named subtree and leaves clearing the whole scene commented out.
2. **Questionable. Action `two-trajectories`.** It sets one configuration per robot at the same origin, so the robots overlap and no trajectory is shown.
3. **Questionable. Action `record-animation`.** It duplicates the `anim` model's code and exports nothing.
4. **Questionable.** `framerate = 1/0.01` assumes a time step that is never tied to the data. `vis`, `mvis`, `X`, `T`, `q`, `mechanism`, `robot_urdf` and `compute_transform` are undefined; the `frame` model uses `vis` before any `Visualizer()`. Check `isopen` and `url` on a `Visualizer` against MeshCat.jl.

**Proposal (thin).** Make the panel self-contained with a double pendulum from RigidBodyDynamics' built-in examples. Simulate it, animate the trajectory at the simulation's own time step, and show two runs side by side (offset with `settransform!`), for example two initial conditions to show chaos. Add a frame and trajectory trace, and a static export (`MeshCat.static_html`) that works without a live server.
