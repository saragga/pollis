How to read the verdicts:

- The verdicts describe each panel as found, before the fixes in this pull request.
- A finding rated **wrong** means the example says something false, or the code cannot show what its label or description promises. **Questionable** means it is defensible but misleading, incomplete, or silent on an assumption that matters. **Minor** means a wording or small correctness point.
- **Fixed** findings were rated wrong and had a local fix: a parameter, a label, a description, a formula or a comment. There is one commit per panel. The other findings are proposals for the panel author, who makes the final call on subject matter.
- Items already tracked are not repeated: the postfix transposes (task 3.3), the `bert` token-attribution gradient, `rl` Flux/Zygote, `kgds`/`diff` mentions, and `rxinfer`'s `gaussian_model` (task 3.4).

## Cross-cutting findings

These apply to several panels in the batch. They are listed once here and referred to below.

- **X1. Zygote through `Flux.gradient`.** `acm` (A2C, SAC, TD3), `autoencoder` (both models) and `azero` all take reverse-mode gradients with `Flux.gradient` / `Flux.withgradient`, which uses Zygote. The policy says reverse-mode AD uses Enzyme. `rl` is already tracked. These three panels are not tracked and should be migrated the same way: `Flux.gradient(f, Duplicated(model))` with Enzyme loaded, as the `rl` Lux branch does. This is not fixed here because it is not a semantic fix, and the change needs running to confirm.
- **X2. DataFrames API on Agents.jl output.** `run!`, `ensemblerun!` and `paramscan` return DataFrames. `abm` (`eachrow`, `filter` on rows, `data.step`), `abmEns` (`groupby`, `combine`, `nrow`, `data[:, [...]]`) and `abmViz` (`data[:, 3]`) use the DataFrames API on them. That makes DataFrames a hidden dependency the reader has to learn, against the Tables.jl policy. `abmEns`'s `equilibrium-summary` already shows the fix: `cols = Tables.columntable(data)`, then work with plain vectors. The extractor's `DataFrames` check misses these because the word never appears.
- **X3. Non-ASCII characters in code.** The extractor checks only for Greek letters. `÷` is used as an operator in `arima` (`acf`, `ljung-box`), `atsf` (`structure`, `residuals`, `backtest`, `compare-methods`) and `autotsf` (default `race` code, `autocorrelation`, `residuals`, `compare-methods`, `combination`): write `div(a, b)`. `×` and `²` appear in comments and strings in `bert`, `bfmb` and `blsdf`: write `x` and `R2`. Suggest extending the extractor's check to all non-ASCII characters in code.
- **X4. Default code with no data.** `ande`, `arima`, `atsf`, `autoencoder`, `autotsf`, `bcf`, `bert`, `bfmb`, `cca`, `attr` and `cds` read variables the user must supply (`y`, `X`, `f`, `R`, `u0`, `p`, `text`). A reviewer cannot check that the method suits the data, and a student cannot see the method find anything. The best panels in the batch (`blsdf`, `ccdr`, `bndt`, `blv`, `azero`, `acm`) simulate data with a known answer and then show the method recovering it. Recommendation: every panel whose default reads user data should also offer a simulated default that has the feature the method is for. Examples: a seasonal series with trend for `arima`/`atsf`/`autotsf`; quarterly log GDP for `bcf`; data with injected anomalies for `ande`; two views sharing a latent factor for `cca`.
- **X5. Actions that ignore the selected model.** In `abm`, every action uses `:mood`, which only the grid model has. In `bcf`, every action calls `hp_filter`, whatever filter is selected ("replace with chosen filter"). A user who picks Graph Space or Baxter-King gets actions about another model. Use `{{?model=...}}` lines, as `atsf` and `adlp` do.

## Panel reviews

### abm: Agent-Based Models

**Sound: wrong. Worth: thin.**

1. **Wrong. `abm.toml`, model `grid`.** The agent is called `SchellingAgent` and the panel cites Schelling (1971), but there is no Schelling rule. No agent has a group, nothing measures similar neighbours, and `move_agent!(a, m)` moves each agent to a random cell every step. `mood` is drawn once and never changes, so every mood-based action is flat. The Convergence Check shows a constant, the Phase Diagram a uniform field, and the Emergent Summary the initial draw. Proposed fix: see the proposal below. This needs a rewrite, so it is not fixed here.
2. **Wrong, fixed (`9ee41c68`). `abm.toml`, model `graph`.** Every agent started `:S`, so no infection could ever spread. The first five agents now start `:I`. Still open: agents never recover (SIR without R), and `infect_neighbours!` is not defined (task 3.4).
3. **Questionable. `abm.toml`, all models.** `agent_step!` is defined after `ABM(...)` is built and is never passed to it. In Agents.jl 6, the step function is a keyword of the model constructor (`StandardABM(A, space; agent_step!)`), so `run!` does not use the rule the code defines. Proposed fix: define `agent_step!` first and pass it to the constructor.
4. **Questionable. `abm.toml`, model `continuous`.** The `Bird` agents move in straight lines at a fixed random velocity. There is no alignment, cohesion or separation, so nothing emerges, although the panel cites Reynolds (1987). The recorded `:speed` is constant.
5. **Questionable. All actions** (X5, X2). They reference `:mood` for all three models, and `initialize_model`, `initialize_grid_model`, `initialize_sir_model` and `init_model(alpha, beta)` are never defined. The Phase Diagram's `alpha` and `beta` are parameters of no model in the panel.

**Proposal (thin).** The panel should answer Schelling's question: *can mild individual preferences produce strong segregation?*

- **Grid default code.** Two groups on a 20x20 grid at 90% density. An agent is happy when at least `min_to_be_happy` (default 0.3) of its neighbours share its group; unhappy agents move to a random empty cell. Record the mean share of same-group neighbours (the segregation index) and the share of happy agents.
- **Actions.**
  - Visualise: snapshots at t = 0 and t = T, and the segregation index over time.
  - Diagnose: the step at which no agent moves any more.
  - Predict: an ensemble over 20 seeds.
  - Compare: a sweep of `min_to_be_happy` from 0.1 to 0.8, showing the jump in segregation.
  - Interpret: "a 30% preference yields about 75% same-group neighbours".
- **Continuous model.** A Vicsek or boids flock, with the polarisation order parameter against the noise level.
- **Graph model.** SIR with recovery. Compare peak and final size across Erdos-Renyi, Watts-Strogatz and Barabasi-Albert graphs with the same mean degree.

### abmEns: Ensemble & Parameter Scanning

**Sound: questionable. Worth: adequate.**

1. **Wrong, fixed (`10f064ea`). `abmEns.toml`, action `ensemble-trajectories`.** The band is mean +/- 1 standard deviation across replications, but it was described and commented as a confidence band. It is the spread of single runs. A confidence interval for the ensemble mean would be +/- 1.96 sd / sqrt(R), about 2.3 times narrower with R = 20. The description and comment now say which one is drawn.
2. **Wrong, fixed (`10f064ea`). Action `oa-vs-factorial`.** It printed `var(final.mean_mood)` as "variance explained", but it is the variance of the outcome over each design. The action now prints "output variance". Its description now says what the numbers mean: for an additive model, the factorial variance equals the sum of the two OAT variances, so a clear excess hints at interaction. Still open: with one run per point (`paramscan` without seeds), run-to-run noise enters every variance. Scan over `:seed` as `equilibrium-summary` does.
3. **Questionable. Default code (both models).** `initialize_model(; seed, threshold, density)` is never defined, so the reader never sees the model being replicated. Since `mood` is static in `abm`, the ensemble would have nothing to average. Proposed fix: define the Schelling model of the `abm` proposal here, or in a shared snippet.
4. **Questionable. Action `sobol-sensitivity`.** Sobol indices of a stochastic model, with one unseeded run per sample, count run-to-run noise as parameter importance. Proposed fix: average several seeds per sample point, or fix the seed, and say which is done.
5. **Minor. Action `paramscan-heatmap`.** `density => 0.0:0.1:1.0` includes an empty grid (0.0). Start at 0.1.
6. **Minor.** X2 (`groupby`, `combine`, `nrow`).

### acm: Actor-Critic Methods

**Sound: sound. Worth: rich.** A self-contained point-mass regulator with A2C, SAC and TD3, checked against the discounted LQR solution and across seeds. The SAC tanh-Gaussian log-density, the TD3 target smoothing and the discounted Riccati iteration are correct.

1. **Questionable. `acm.toml`, model `a2c`.** `steps = 20000 # environment steps` is shared by all three models. A2C counts `total` per environment and runs `nenvs = 16` environments, so it collects 16 x 20000 = 320000 transitions against 20000 for SAC and TD3. The learning curve plots `total * nenvs`, so its x-axis is honest, but the LQR and seed comparisons compare methods on unequal budgets. Proposed fix: stop A2C at `total * nenvs >= steps`, or say on the `nenvs` line that A2C gets 16 times the transitions.
2. **Minor. Model `a2c`.** The recorded `actor_loss` history is recomputed with the updated network and without the `- ls` term of the log-density, so the Actor Loss plot is not the objective that was optimised.
3. **Policy.** X1 (Zygote).

### adlp: AD Log-Likelihood

**Sound: sound. Worth: rich.** Simulated data with known parameters, an Enzyme gradient checked against finite differences and ForwardDiff, reference fits, and Hessian standard errors.

### ande: Learning-Based Anomaly Detection

**Sound: questionable. Worth: adequate.**

1. **Questionable. `ande.toml`, all models.** `X`, `anom_idx` and `X_new` are never defined (X4). With no data containing known anomalies, the panel cannot show whether any detector works: no precision, recall or precision-at-k. Proposed fix: simulate a Gaussian cloud with about 5% injected outliers and `anom_idx` known, then add a Diagnose action with precision and recall at the 5% threshold.
2. **Questionable. Models `deepsad` and `esad`.** "Unlabelled rows are treated as normal" (`y = fill("normal", n)`): every row not in `anom_idx` is labelled normal. Deep SAD is semi-supervised. Its point is to learn from a few labels plus unlabelled data, which OutlierDetection.jl marks as `missing`. Labelling everything turns it into supervised learning and hides the anomalies nobody has labelled yet. Proposed fix: `y = Vector{Union{Missing, String}}(missing, n)`, then set a few known normals and known anomalies.
3. **Minor.** The comment "flag the top 0.05 of scores" should read "the top 5%". The threshold is a contamination assumption; say so.

### atsf: Advanced Time-Series Forecasting

**Sound: sound. Worth: rich.** Syntetos-Boylan classification with the right thresholds (ADI 1.32, CV2 0.49), holdout scoring, and naive benchmarks.

1. **Questionable. `atsf.toml`, action `backtest`.** MASE is scaled by the non-seasonal naive error (`mean(abs.(diff(train)))`) even for monthly data with period 12. For seasonal data the usual scale is the seasonal naive error (Hyndman and Koehler 2006), as `autotsf` does. Proposed fix: use `train[m+1:end] .- train[1:end-m]` when m > 1.
2. **Minor. Action `residuals`.** The description says Ljung-Box up to "lag 2 x period (lag 10 for non-seasonal data)", but the code uses `min(24, n / 4)` for every model, including intermittent demand. Ljung-Box on Croston residuals is of little use; drop it for `demand`.
3. **Minor.** X3, X4.

### attr: Attractor & Basin Analysis

**Sound: wrong. Worth: adequate.**

1. **Wrong, fixed (`ed1ab557`). `attr.toml`, model `attract`, actions `attractor-plot`, `attractor-change`, `tipping-point`, `single-vs-multi`.** `extract_attractors(mapper)` returns only the attractors a recurrence mapper has met while mapping initial conditions. On a fresh mapper that is none, so these reported "0 attractors", and "Multistable (0 attractors)". Each now maps 200 random initial conditions from the grid (`basins_fractions`) first. Please check the `statespace_sampler(grid, seed)` form in task 3.4; the `bifur` model uses an older keyword form.
2. **Wrong, fixed (`ed1ab557`). Action `basin-entropy`.** `basin_entropy` returns `(Sb, Sbb)`, and the comment's criterion ("> 0.5 indicates fractal boundaries") was wrong. The sufficient condition of Daza et al. (2016) is boundary basin entropy Sbb > log 2. The action now prints both and applies that test.
3. **Wrong, fixed (`ed1ab557`). Action `mappers`.** "Compare AttractorsViaRecurrences and AttractorsViaProximity" ran only the recurrence mapper. It now builds the proximity mapper from the attractors found and compares basin fractions on the same random initial conditions.
4. **Questionable. The whole panel.** The system is Lorenz with user `p`, presumably sigma = 10, rho = 28, beta = 8/3. At those values the Lorenz system has a single chaotic attractor, so basin portraits are one colour, basin fractions are 100%, and basin entropy is 0: the methods have nothing to find. Proposed fix: use a multistable example, or set rho in (24.06, 24.74), where the chaotic attractor coexists with two stable fixed points. The `tipping-point` sweep does cross that window, but with 40 points only one or two land in it. Candidate examples:
   - the Duffing oscillator (two wells);
   - the magnetic pendulum (three basins with fractal boundaries);
   - Lorenz with rho = 24.4.
5. **Questionable. All models.** A 20 x 20 x 20 grid over [-30, 30]^2 x [0, 60] has cells 3 units wide. That is coarse for the Lorenz attractor, and recurrence mappers can split one chaotic attractor into several at that resolution. Check the count against a finer grid.
6. **Minor.** `lorenz!` is not exported by Attractors (use `PredefinedDynamicalSystems.lorenz()` or define it, as `cds` does). `correlationdim` is `grassberger_proccacia_dim` in current FractalDimensions (task 3.4).

### bcf: Business Cycle Filters

**Sound: questionable. Worth: adequate.** The filter settings are the standard quarterly ones: HP lambda = 1600; Baxter-King 6 to 32 quarters with K = 12; Hamilton h = 8, p = 4.

1. **Wrong, fixed (`7e9f1a93`). `bcf.toml`, action `variance_ratio`.** `var(trend) / var(y)` and `var(cycle) / var(y)` were printed as the "fraction explained by" trend and cycle. They add to one only with `2 cov(trend, cycle) / var(y)`, and filters do not make trend and cycle orthogonal. The action now prints the covariance share too and says when the shares can be read as variance explained. Still open: for an I(1) series, var(trend) grows with the sample, so the ratio depends on the sample length.
2. **Questionable. All models.** Nothing says what `y` should be. These filters are meant for 100 x log of a quarterly real series, so the cycle is in percent deviations. The default prints `std(cycle)` without units. Proposed fix: a simulated or documented default (for example, 100 x log real GDP), with the unit in the comment.
3. **Questionable. All actions** (X5). Each action calls `hp_filter` whatever model is selected.
4. **Questionable. Action `filter_comparison`.** The Hamilton cycle loses the first h + p - 1 = 11 observations and Baxter-King loses K = 12 at each end. `cor(c, hp_cyc)` then compares vectors of different lengths, or misaligned periods if they are padded. Proposed fix: align all cycles on their common sample before comparing. This comparison is also where Hamilton's (2018) critique of HP belongs: show the HP cycle of a pure random walk.
5. **Minor. Action `cross_correlation`.** The description says "e.g. GDP growth", but the code correlates with the HP cycle of `gdp`. Action `spectrum` returns raw periodogram ordinates without converting frequencies to periods in quarters, so the reader cannot see whether 6 to 32 quarters dominate.

### bert: BERT Embeddings

**Sound: questionable. Worth: adequate.**

1. **Wrong, fixed (`c9a3f036`). `bert.toml`, all snippets.** The checkpoint input was substituted bare: `load_tokenizer(bert-base-uncased)` reads as `bert - base - uncased`. The template now quotes it.
2. **Questionable. Model `similarity`, actions `similarity-heatmap`, `nearest-neighbour`, `top-similar`.** They present cosine similarity of the raw CLS vector of a pre-trained, not fine-tuned BERT as semantic similarity. That representation is known to be poor for similarity: embeddings are anisotropic and most pairs score above 0.8 (Reimers and Gurevych 2019). Proposed fix: say so in the description, and make the `compare-models` contrast the point of the panel, with a sentence-transformers checkpoint and mean pooling.

4. **Questionable. Action `compare-pooling`.** It compares only the norms of the CLS and mean-pooled vectors, which says nothing about which represents meaning better. Compare the similarity of a paraphrase pair and an unrelated pair under each pooling. `mean` also needs `using Statistics`.

### bfmb: Fama-MacBeth Regression

**Sound: questionable. Worth: rich.** The actions are good: Bayesian against classical, OLS against GLS, and credible intervals against t statistics.

1. **Wrong, not fixed. `bfmb.toml`, model `bayesian`.** The default code passes `psi0`, `d`, `intercept` and `burnin` to `BayesianFM`, and describes them as "prior scale on risk prices" and "prior weight on pricing errors". Those are hyperparameters of `BayesianSDF` (as `blsdf` uses them). `BayesianFM(f, R, sim_length)` in Bryzgalova, Huang and Julliard (2023) has flat priors, and returns `lambda_ols_path` and `R2_ols_path`, which the actions use, not `lambda` and `R2_oos`. So the default code and the actions describe different estimators. Proposed fix:

   ```julia
   result = BayesianFM(f, R, 10_000)
   lam = result.lambda_ols_path[:, 2:end]
   lambda_mean = vec(mean(lam, dims=1))
   ```

   Then drop the `psi0`, `d`, `intercept` and `burnin` inputs for this model. This is not fixed here because it removes four inputs; please confirm the API in task 3.4.
2. **Questionable. Action `bayes-vs-classical`.** "Bayesian shrinks weak factors toward zero": Bayesian Fama-MacBeth with flat priors does not shrink. For a weak or useless factor its posterior stays wide and centred near zero, instead of the spuriously tight estimate the two-pass method gives. That is the point of BHJ (2023), and the comment should say so. Shrinkage comes from the spike-and-slab SDF in `blsdf`.
3. **Minor. Action `posterior-predictive`.** It treats the betas as fixed, so the 90% band understates uncertainty. Say "given the estimated betas".
4. **Minor.** X3 (`²`), X4 (`f`, `R`).

### bndt: Bandit Problems
