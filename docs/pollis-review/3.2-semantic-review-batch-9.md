# 3.2 Semantic review of the code examples, batch 9

Task 3.2 of the Pollis Polish Roadmap. Batch 9 is files 193 to 209 of `LC_ALL=C ls src/vs/workbench/contrib/model/browser/webviews/*.toml`, from `ssm` to `yfin`, the last files in the list. All 17 panels were reviewed.

The code was read as `node build/pollis/extractCodeExamples.ts` renders it (`.build/code-examples/<id>/<model>.jl`), covering the default code of every model and every Next Steps action, with each input at its default. No Julia was run; task 3.4 runs the code. Wikis and notebooks are out of scope. Verdicts, finding ratings and the "fixed" rule follow the batch 1 report (`3.2-semantic-review-batch-1.md`). A panel with a finding rated wrong is rated at least questionable, even when that finding is fixed here.

Where a finding depends on a package's API, I checked the package source on GitHub, and the finding says so. The packages checked were LowLevelParticleFilters.jl, StateSpaceModels.jl, TradingAgents.jl, Brokerage.jl, VLLimitOrderBook.jl, LSurvival.jl, MacroEconometricModels.jl and XLSX.jl, plus the General registry. Items already tracked elsewhere are not repeated: postfix transposes, `bert` token attribution, `rl` Zygote, the `kgds`/`diff` mentions and `rxinfer`'s `gaussian_model`.

## Cross-cutting findings

- **R1. Invented package APIs.** This is the batch's main problem. Four panels call functions that their packages do not have:
  - `trad`: all three packages.
  - `tsls`: Microeconometrics.jl.
  - `var`: MacroEconometricModels.jl.
  - `ssm`'s `rbf`: `RaoBlackwellizedParticleFilter`.

  These need rewrites against the real APIs, so they are reported, not fixed. Smaller cases were fixed in place, because the real call has the same shape:
  - `tssm`'s StateSpaceModels calls;
  - `ssm`'s `simulate`, `smooth` and `sol.yhat`;
  - `xlsx`'s `setConditionalFormat`.
- **R2. Actions that ignore the selected model.**
  - Every `ssm` action ran on `filter`, which is `Base.filter`, not the panel's filter (fixed).
  - The `tssm` actions used `model` and `update_hyperparameters!`, which only the `lg` branch defines, and not correctly (fixed).
  - The `var` `svar` actions rebuild the reduced-form VAR, so the "structural" impulse responses ignore the identification (not local).
- **R3. Packages that are assumed to re-export what they do not.** LowLevelParticleFilters does not re-export `I` (LinearAlgebra) or `MvNormal` (Distributions), so every `ssm` and `tssm` filter branch failed on its first line (fixed). Also, `kurtosis` and `autocor` live in StatsBase, not Statistics (`trad`, fixed).
- **R4. Outputs that say something other than what they compute.**
  - `swarm` measured the distance to the origin for Rosenbrock, whose minimum is at all ones.
  - `tsls` printed a raw coefficient gap as "Hausman diff".
  - `trad` printed percent labelled as basis points.
  - `tsf` called seasonal ETS "simple exponential smoothing".
  - `vm` printed a bipower variation off by pi/2.
  - `ssm` printed `mean.(sol.x)`, which averages the components of each predicted state.

  All of these were fixed.
- **R5. Non-ASCII operators in code.** `trad` and `tsf` used the non-ASCII division operator (U+00F7), and `xlsx` printed an arrow. All three were fixed.

### traj: Trajectory Optimisation

**Questionable, rich.** Pendulum swing-up with four methods on a shared RK4 model and cost:
- ALTRO-style augmented Lagrangian iLQR with control bounds;
- iLQR/DDP;
- direct trapezoidal collocation (JuMP and Ipopt);
- indirect shooting on Pontryagin's conditions (NLsolve).

I checked the iLQR backward pass (`Vx`, `Vxx`, the regularisation, the line search), the time-varying LQR Riccati recursion and the augmented Lagrangian update. The actions include feasibility rollouts, solver convergence, replanning, disturbance rejection with TVLQR feedback, the discretisation, model mismatch, a cost breakdown and gains.

1. **Wrong, fixed (`cfa44004`). `indirect`.** The other methods minimise the sum of `stage(x, u)` over the intervals, which is the integral of `stage / dt`. The Hamiltonian used `stage` itself. So the indirect method weighted the running cost 1/dt = 20 times less against the terminal penalty and solved a different problem, and its cost was not comparable with the other methods'. The Hamiltonian is now `stage / dt + lambda' f`, and the control law is `u = -dt R^-1 f_u' lambda`.
2. **Questionable. `indirect`.** Single shooting from `lambda0 = 0` on a swing-up is very sensitive, so `nlsolve` may not converge. The Solver Convergence action shows the flag. A multiple-shooting variant, or a warm start from the iLQR costates, would be more reliable.

### tsls: Two-Stage Least Squares (2SLS)

**Wrong, thin.** One model. Its six actions each refit the same 2SLS model and print one more attribute of it.

1. **Wrong, not local. All code (R1).** Microeconometrics.jl has no `fit(IV(Homoscedastic()), df; response, regressors, endogenous, instruments)`. The real API builds `Microdata(df, Dict(:response => "y", :control => "1 + x1 + x2", :treatment => "w1", :instrument => "z1 + z2"); vcov = Homoscedastic())` and calls `fit(IV, D)` or `fit(OLS, D)`. The current code also has no intercept.
2. **Wrong, not local. Inputs.** `[:{{exog}}]` with the default `x1 x2` renders `[:x1 x2]`, where `x2` is an undefined variable. The first-stage regressors render `[:x1 x2, :z1 z2]`, which is a syntax error. A formula-string input, as the real API takes, avoids both.
3. **Wrong, fixed (`435dcb8a`). Action `residuals`.** The residual standard deviation divided by n - 2 whatever the number of coefficients. It now uses n - k.
4. **Wrong, fixed (`435dcb8a`). Action `ols_comparison` (R4).** The raw coefficient gap was printed as "Hausman diff". A Hausman test scales the gap by the difference of the covariance matrices, so the line is now labelled as a raw gap.
5. **Questionable. Action `first_stage`.** The description promises the F > 10 rule, but no F statistic is computed, and only the first endogenous variable is used.

**Proposal (thin).** Rewrite the panel on the real `Microdata` API, with a simulated default where the true effect is known and an unobserved confounder biases OLS. The actions would then show:
- the OLS bias next to the 2SLS estimate;
- the first-stage F (or Cragg-Donald / Kleibergen-Paap with several instruments);
- the Sargan-Hansen over-identification test;
- a Durbin-Wu-Hausman test through the control-function regression;
- robust and clustered standard errors from the existing vcov input;
- an Anderson-Rubin confidence set that stays valid with weak instruments;
- a weak-instrument sweep that shrinks the first-stage coefficient and shows 2SLS drifting towards OLS.

### vm: Volatility Measurement

**Questionable, rich.** It has three intraday estimators (realized, bipower and two-scales) and four range-based estimators (Parkinson, Garman-Klass, Rogers-Satchell and Yang-Zhang). The actions include rolling estimates, the BNS jump test, an EWMA forecast, benchmarks, annualisation and regimes. The GK, Parkinson and RS formulas and the BNS tripower quarticity check out.

1. **Wrong, fixed (`affac310`). `yz`.**
   - Yang and Zhang's MSE-minimising weight is k = 0.34 / (1.34 + (n+1)/(n-1)); the code divided by 1 + (n+1)/(n-1).
   - The default also passed k = 0.34, which is alpha, not k. k is about 0.14 for long samples, so the optimal weight was never used, and the tooltip called 0.34 an approximation.

   The default is now `nothing`, which selects the optimal weight.
2. **Wrong, fixed (`affac310`). `bpv` (R4).** The bipower variation was printed without its pi/2 factor, so it was not on the scale of the realized variance it is compared with.
3. **Questionable. Action `bns`.**
   - The test's asymptotics are for intraday returns within a day. The daily models apply it to close-to-close returns (the comment says so), and `park` applies it to log ranges, which are not returns.
   - Jumps only make RV exceed BV, so a one-sided test is the right one, not |Z| > 1.96.
4. **Questionable. `tsv`.** The two-scales estimate can be negative in small samples, and `sqrt` then throws. That is likely in the 21-observation rolling window with K = 5. It also divides by the number of prices, not the number of returns.
