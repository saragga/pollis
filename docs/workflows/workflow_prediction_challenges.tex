\section{The package PollisCompetitions.jl}
\label{sec:package}

PollisCompetitions.jl is a Julia package of PollisRegistry, installed with \file{Pkg.add("PollisCompetitions")} the
first time a page needs it. It holds three catalogues as TOML, the data of the built-in datasets as Parquet, the
functions that read and score them, and a module of eight statistical benchmarks. DuckDB
\dcite{RM2019a}{(Raasveldt and Mühleisen, 2019)} does the reading and the arithmetic: the Parquet files are read where
they lie, never copied into a database file.

\subsection{The module Benchmarks}

\file{PollisCompetitions.Benchmarks} forecasts a single series from its values alone, and never reads a dataset. That
is why the agents of Agents' Forecasting Competition may use it and must not use the rest of the package. It exports
\file{BENCHMARKS}, \file{benchmarks}, \file{holt}, \file{is_seasonal}, \file{seasonal_index}, \file{ses} and
\file{theta}.

\begin{itemize}
  \item \textbf{Naive} repeats the last value; \textbf{sNaive} the last period of values.
  \item A series that passes \file{is_seasonal} is divided by its classical multiplicative seasonal index
    (\file{seasonal_index}); \textbf{Naive2}, \textbf{SES}, \textbf{Holt}, \textbf{Damped} and \textbf{Theta}
    \dcite{AN2000a}{(Assimakopoulos and Nikolopoulos, 2000)} forecast the adjusted values, which are multiplied back by
    the last period of the index.
  \item \textbf{Com} is the mean of SES, Holt and Damped.
\end{itemize}

\sig{benchmarks(y; period, horizon, methods)} gives the forecasts of each method named. A method that cannot be fitted
to a series raises an error, and the pages then leave that benchmark out of the table rather than score it on fewer
series.

\subsection{How a forecast is scored}

\file{score} works in a DuckDB database in memory, in four steps.
\begin{enumerate}
  \item \file{prepare!} makes three tables: \file{known_series}; \file{test_values}, the held-out values with \file{h}
    from 1; and \file{scales}, the mean absolute difference between each training value and the one a seasonal period
    before, the denominator of MASE \dcite{HK2006a}{(Hyndman and Koehler, 2006)}.
  \item \file{given!} reads your forecasts and refuses series the dataset does not have.
  \item \file{errors!} gives the sMAPE and the MASE of each series, the means over its horizon, and refuses a series
    not forecast once at each step.
  \item \file{reference!} computes Naive2 on the same series. \file{summary} averages the errors by frequency, by
    domain and in total, and weighs them against Naive2 into OWA
    \dcite{MSA2020a}{(Makridakis, Spiliotis and Assimakopoulos, 2020)}.
\end{enumerate}

The result is a table of \file{measure}, \file{breakdown}, \file{level} and \file{value}, where \file{level} is a
frequency, a domain or \file{Total}.

\section{The TOML files}
\label{sec:toml}

Every file is plain TOML and edited by hand. A field left out is unknown, and loads as NULL (\file{missing} in Julia).

\subsection{The Dataset Catalog: metadata/datasets.toml}

There is one \file{[[datasets]]} table for each dataset, with its works as \file{[[datasets.references]]}.

\begin{lstlisting}
[[datasets]]
dataset_id = "tourism_2011"                 # the key, and the name of its folder
dataset_name = "Tourism Forecasting Competition"
competition_name = "Tourism Forecasting Competition"   # given with competition_year, or neither
competition_year = 2011
topic = "Tourism"
data_structure = "Time-Series"              # Cross-section | Time-Series | Panel | Images
geometry = "None"                           # None | Spatial Weights Matrix | Coordinates | Polygons
response_type = "Continuous"                # Binary | Multiclass | Ordered | Count | Survival | Continuous | Text
rows = 164581
features = 0
size_mb = 0.45                              # Parquet files if built in; files downloaded if not
licence = "CC BY 4.0 (via the Monash archive on Zenodo)"
delivery = "Built-in"                       # Built-in | Download
source_url = "https://..."

  [[datasets.references]]
  bibtex_key = "AHSW2011a"                  # a key of PollisReferences
  role = "Competition"                      # Primary | Competition | Benchmark | Other
\end{lstlisting}

The same \file{[[datasets]]} tables come from two other contributors. An installed toolbox names a file of them in
\file{forecastingDatasets} of its \file{pollisToolboxes} contribution, and a dataset you add has them in its
\file{dataset.toml} (\S\ref{sec:workspace}). Manage Challenge Datasets reads all three and checks each against the
schema that Pollis ships, \file{compose/browser/media/forecastingCatalogue.toml}. That schema has 17
\file{[[field]]} tables (name, label, group, type, \file{controlled} and \file{values}, description) and four
\file{[[view]]} tables, the column presets of the page (id, label, \file{pinned}, \file{columns}). The page's own TOML
adds the curated collections as \file{[[collections]]} (id, name, year, url, description, \file{datasets} and
\file{papers}).

\subsection{The Model Catalog: metadata/models.toml}
\label{sec:modelcatalog}

\begin{lstlisting}
[[models]]
model_id = "tabarena_limix_2_1016_default"
model_name = "LimiX-2-1016 (default)"
estimator_family = "Foundation Model"       # one of nine families
estimator_method = "Pretrained in-context learner"   # one of the methods of its family
package = "LimiX"
language = "Python"                         # Julia | Python | R | C/C++ | Fortran
                                            # julia_package = "LightGBM": where it is in Julia (left out: nowhere)
                                            # julia_checked = false: true once it gives the published scores

  [[models.references]]
  bibtex_key = "ZRYZT...2026a"
  role = "Methodology"                      # Methodology | Software | Other
\end{lstlisting}

There are nine families: Foundation Model, Tree-based, Neural Network, Baseline, Statistical, Kernel Methods, Fuzzy
System, Hybrid and Other. Each has a closed list of methods, which the header of \file{models.toml} gives and
\file{ESTIMATOR_METHODS} checks. A Hybrid model's method names the methods it combines.

\file{julia_package} says where the model is in Julia: the registered package that has its estimator, written in Julia
or bound to the compiled library the original runs (a package that runs Python does not count), for every
configuration of the model, default or tuned; \file{ModelZoo} for a model of ModelZoo.jl; left out when no package
has it. \file{julia_checked} is true when that package, run on the benchmark's splits, gives the published scores,
and false when it has the same estimator but has not been checked against them. The two are given together.

A model counts as checked only on the benchmark's own splits, with the model's own settings: a package with the same
estimator can still give other scores, through its defaults, the preparation of the data or its random numbers. A
foundation model needs the weights its authors trained, which no port of its code gives.

\subsection{Which models ModelZoo.jl writes}

ModelZoo.jl (\file{github.com/Trumpingtons/ModelZoo.jl}, MIT) holds the models of the Model Catalog that no registered
Julia package has, and the measures by which Score Models scores tabular and survival datasets. A model is written
into it when:

\begin{itemize}\setlength{\itemsep}{1pt}
\item no registered Julia package has its estimator, written in Julia or bound to the compiled library the original
  runs;
\item its benchmark publishes scores that can check it: scores on splits that PollisCompetitions.jl has, of a
  configuration whose settings are known. A model tuned by a search the benchmark did not publish (Bayesian
  optimisation, or the cross-validation of its own package) was fitted with settings that are not known, so its
  published scores cannot check a port;
\item it needs no pretrained weights. Families with heavy dependencies, such as neural networks, are to come as
  package extensions, which load only with the package they need, so that the core stays light.
\end{itemize}

The rules are the same for every model, whichever benchmark or competition scored it. Each model is written from its
papers and the documented behaviour of the software the benchmark ran, never translated line by line from a package
under another licence; where the documentation leaves behaviour out, the source of a package under the MIT licence is
read for it. Its test checks that it is the benchmark's model, on a few datasets the test chooses by a stated rule: it
fits the model on every split of those datasets and compares its scores with the published ones, split by split or as
means over the splits.

\subsection{The models of ModelZoo.jl 0.1.2}

\textbf{Cox GAM} (\sig{CoxGAM}), the GAM of the Low-Dimensional Survival Benchmark
\dcite{BZBBW...2026a}{(Burk, Zobolas, Bischl, Bender, Wright and Sonabend, 2026)}, which fitted mgcv's \sig{gam} with
the Cox family. It is Cox's proportional hazards model with a thin plate regression spline
\dcite{Woo2003a}{(Wood, 2003)} of dimension 10 for each numeric covariate with 10 or more distinct values, and the other covariates linear. The coefficients maximize the
partial likelihood, with Breslow's handling of ties, penalized by the wiggliness of the splines; the smoothing
parameters minimize the REML criterion of \dcite{WPS2016a}{Wood, Pya and Säfken (2016)} by Newton's method
\dcite{Woo2011a}{(Wood, 2011)}, from three starts, keeping the lowest minimum. \sig{linear_predictor} and \sig{survival} give the log relative risk and the
survival of new rows. Checked on 15 of the 34 survival datasets: the means over the splits of the eight measures are
within a relative $10^{-3}$ of the published ones ($5\times10^{-2}$ for D-calibration). On the other datasets a test row
has a level of a factor that no training row has (the benchmark imputes it at random), a smooth covariate has more than
2000 distinct values (mgcv builds its spline on 2000 drawn at random), or, on splits of 9 datasets listed in the test,
mgcv stopped at smoothing parameters whose REML criterion is higher than at those \sig{CoxGAM} reaches.

\textbf{ExtraTrees} (\sig{ExtraTrees}, \sig{BaggedExtraTrees}), TabArena's ExtraTrees
\dcite{EPTHD...2025a}{(Erickson and 6 coauthors, 2025)} in its default, tuned, and tuned and ensembled configurations.
Forests of extremely randomized trees \dcite{GEW2006a}{(Geurts, Ernst and Wehenkel, 2006)} with scikit-learn's settings
as AutoGluon fits them: 300 trees, each on a bootstrap sample of the rows, grown until its leaves are pure or it has
15000 leaves, each node split at the best of random splits of $\sqrt{p}$ covariates for classes and all $p$ for
numbers; a row whose value is missing goes to a side drawn at random. \sig{BaggedExtraTrees} averages 8 forests, each
fitted without one of 8 folds of the rows, as TabArena's default configuration. Checked, for the default, on the
smallest dataset of each Response Type among those TabArena scored the model on whose covariates are all numbers with
none missing: blood\_transfusion (Binary, ROC AUC), qsar\_fish\_toxicity (Continuous, RMSE) and maternal\_health\_risk
(Multiclass, log loss). Every one of their 30 splits is fitted and scored, and the mean of the differences from
TabArena's scores on the same splits is within 4 standard errors of 0. The trees draw other random numbers than
scikit-learn's, so the two agree in distribution, not split by split. The tuned configurations share the estimator and
are not checked.

\textbf{APLR} (\sig{APLR}, \sig{BaggedAPLR}), TabArena's APLR in the same three configurations: automatic piecewise
linear regression \dcite{OD2024a}{(von Ottenbreit and De Bin, 2024)} with the defaults of the Python package aplr 10.26.
It is gradient boosting of terms that are linear effects or hinge functions of one covariate, $\max(x-s,0)$ or
$\min(x-s,0)$, set to 0 where a hinge function of another covariate in the model is 0, an interaction of two
covariates. Each of up to 3000 steps moves the intercept, then adds the term, among the 7 that fitted best lately,
whose coefficient, fitted to the negative gradient by least squares and shrunk by the learning rate 0.5 (and by half for
an interaction), reduces the squared error most; split points are searched among the boundaries of up to 300 bins of
the covariate. Validation rows choose the number of steps, boosting stopping after 200 steps without a lower validation
error. Numbers use the squared error loss, their predictions kept within the range of the training predictions and
responses; classes are modelled one against the rest by the logit link. \sig{BaggedAPLR} averages 8 models, each with
one of 8 folds of the rows as its validation rows, as TabArena's default configuration. aplr's source (MIT) was read
for the behaviour its documentation leaves out. Checked as ExtraTrees, on the same three datasets, which the same rule
chooses: the mean of the differences is within 4 standard errors of 0, as AutoGluon splits the rows into its folds
with other random numbers.

\textbf{Flex} (\sig{FlexibleSurvival}), the Flex of the Low-Dimensional Survival Benchmark, tuned on Harrell's C and on
the integrated survival Brier score: the flexible parametric survival model of
\dcite{RP2002a}{Royston and Parmar (2002)} on the proportional hazards scale. The log cumulative hazard is a natural
cubic spline of log time, with boundary knots at the smallest and largest log event times and $k$ internal knots at
their quantiles, as flexsurv's \sig{flexsurvspline} places them, plus a linear function of the covariates; the
likelihood is concave in the coefficients, and Newton's method maximizes it. The benchmark tuned $k$ from 1 to 10 on
inner splits it did not publish, so the test fits every $k$ on every outer split of the three smallest survival
datasets without factors (wbc1, e1684 and carpenter\_fda\_data, 90 splits) and asks that each published score be that
of one $k$. Harrell's and Uno's C are both within $10^{-6}$ of one $k$'s on 76 of the 90 splits, and the integrated
Brier score and log loss within $10^{-3}$ on 89. On the other splits flexsurv's search stopped short of the maximum of
the likelihood, which \sig{FlexibleSurvival} reaches; each is listed in the test, checked with flexsurv 2.3.2 on the
same training rows. Both tuned models are checked.

\subsection{Keeping the list current}

ModelZoo.jl's README lists its models, and this section follows it: each release of ModelZoo.jl that adds a model
updates the table of totals and adds the model here, with its benchmark, its method, its check and its papers. The
release of PollisCompetitions.jl that goes with it names ModelZoo in \file{julia_package} of the models it adds, and
sets \file{julia_checked} for those its tests check.

\section{The database}
\label{sec:database}

\file{PC.connect_db()} builds the database in memory, or in a file when given a path. PollisDB opens it as
\file{PollisCompetitions} in the Databases view. It has the five metadata tables, loaded from the three TOML files;
the view \file{model_comparisons}; and a schema for each dataset whose data are on this computer, with a view for each
of its Parquet files. Every table, view and column carries a comment (\file{describe_db}), which the Databases view
shows.

\subsection{The five tables and the view}

\begin{lstlisting}[language=SQL]
CREATE TABLE dataset_catalog (
  dataset_id TEXT PRIMARY KEY, dataset_name TEXT NOT NULL,
  competition_name TEXT, competition_year INTEGER,
  topic TEXT NOT NULL,
  data_structure TEXT CHECK (data_structure IN ('Cross-section', 'Time-Series', 'Panel', 'Images')),
  geometry TEXT CHECK (geometry IN ('None', 'Spatial Weights Matrix', 'Coordinates', 'Polygons')),
  response_type TEXT CHECK (response_type IN ('Binary', 'Multiclass', 'Ordered', 'Count', 'Survival', 'Continuous',
    'Text')),
  rows BIGINT CHECK (rows > 0), features INTEGER CHECK (features >= 0), size_mb DOUBLE CHECK (size_mb >= 0),
  licence TEXT, delivery TEXT CHECK (delivery IN ('Built-in', 'Download')), source_url TEXT,
  CHECK ((competition_name IS NULL) = (competition_year IS NULL)));

CREATE TABLE dataset_references (
  dataset_id TEXT REFERENCES dataset_catalog, bibtex_key TEXT,
  role TEXT CHECK (role IN ('Primary', 'Competition', 'Benchmark', 'Other')),
  PRIMARY KEY (dataset_id, bibtex_key));

CREATE TABLE model_catalog (
  model_id TEXT PRIMARY KEY, model_name TEXT NOT NULL,
  estimator_family TEXT NOT NULL, estimator_method TEXT NOT NULL,   -- a method of its family
  package TEXT, language TEXT CHECK (language IN ('Julia', 'Python', 'R', 'C/C++', 'Fortran')),
  julia_package TEXT, julia_checked BOOLEAN,        -- both given, or neither
  CHECK ((julia_package IS NULL) = (julia_checked IS NULL)));

CREATE TABLE model_references (
  model_id TEXT REFERENCES model_catalog, bibtex_key TEXT,
  role TEXT CHECK (role IN ('Methodology', 'Software', 'Other')),
  PRIMARY KEY (model_id, bibtex_key));

CREATE TABLE benchmarks (
  run_id TEXT, model_id TEXT REFERENCES model_catalog, dataset_id TEXT REFERENCES dataset_catalog,
  split_protocol TEXT, metric TEXT, score DOUBLE,
  PRIMARY KEY (run_id, metric));                 -- one row per run and metric

CREATE VIEW model_comparisons AS
SELECT b.run_id, b.model_id, m.model_name, m.estimator_family, m.estimator_method, m.package, m.language,
  m.julia_package, m.julia_checked, b.dataset_id, d.dataset_name, d.data_structure, d.geometry, d.response_type,
  b.split_protocol, b.metric, b.score
FROM benchmarks b JOIN model_catalog m USING (model_id) JOIN dataset_catalog d USING (dataset_id);
\end{lstlisting}

\subsection{A schema for each dataset}

For each dataset of the catalogue, \file{connect_db} looks for its folder by the rule of \S\ref{sec:folders}. When the
folder has Parquet files, it creates a schema named after the dataset id, with a view named after each file:

\begin{lstlisting}[language=SQL]
CREATE SCHEMA "tourism_2011";
CREATE VIEW "tourism_2011"."series"       AS SELECT * FROM read_parquet('.../tourism_2011/series.parquet');
CREATE VIEW "tourism_2011"."observations" AS SELECT * FROM read_parquet('.../tourism_2011/observations.parquet');
\end{lstlisting}

An id that is already the name of a schema of DuckDB stops the build with an error, rather than shadowing the schema.

\begin{center}\footnotesize
\renewcommand{\arraystretch}{1.2}
\begin{tabularx}{\linewidth}{@{}p{0.2\linewidth}L@{}}
\toprule
\textbf{View} & \textbf{Columns}\\
\midrule
\file{series} & \file{series} (its number), \file{competition} (the dataset id), \file{name} (as the source names it), \file{frequency}, \file{period} (1 for none), \file{horizon}, \file{domain}, \file{start}\\
\file{observations} & \file{series}, \file{t} (from 1), \file{value}, \file{split}: \file{train}, a value the forecasters saw, or \file{test}, one their forecasts are scored on\\
\file{data} & A row per case of a tabular dataset: the response, named by \file{target} in \file{info.toml} (for a survival dataset, the time, with the event indicator named by \file{event}), and its features\\
\file{splits} & \file{row} (of \file{data}, from 1), \file{repeat}, \file{fold}: the fold whose test set the row is in\\
\bottomrule
\end{tabularx}
\end{center}

For example, the best tabular models on one dataset:

\begin{lstlisting}[language=SQL]
SELECT model_name, estimator_family, score
FROM model_comparisons
WHERE dataset_id = 'heloc' AND metric = 'roc_auc'
ORDER BY score DESC LIMIT 10;
\end{lstlisting}

\section{The folders on your computer}
\label{sec:folders}

\subsection{Where the data of a dataset are}

There is one rule for every dataset. Its folder is \file{data/builtin/<id>} of the package if that exists, else
\file{~/.pollis/competitions/<id>} when an \file{info.toml} is there. The data of a dataset whose delivery is Download go
into the second folder. The three pages only read these folders.

\begin{lstlisting}
<package>/data/builtin/<id>/       or    ~/.pollis/competitions/<id>/
  info.toml
  series.parquet                          a dataset of series (format monash)
  observations.parquet
  data.parquet                            a tabular dataset (format tabular)
  splits.parquet
\end{lstlisting}

\subsection{The runs of Score Models}

Each run is a folder of \file{~/.pollis/competitions/runs}, named after the dataset, the frequency and the time; a run of several datasets is named
\file{datasets-} and the time, such as \file{datasets-20261120-101500}. A run holds datasets of one kind: series,
tabular or survival.

\begin{lstlisting}
~/.pollis/competitions/runs/<run>/
  run.toml          the choices of step 1
  method.jl         your forecast(y, h, period), or predict, as step 2 held it
  run.jl            the script the page writes and the Julia REPL runs
  progress.json     {"done", "total", "seconds", "failed"}, every hundredth of the series, or after each split
  forecasts.csv     series,h,value (series)
  scores.csv        repeat,fold, a column per measure, seconds (tabular and survival)
  published.tsv     model id, name, measure, score: the published runs (tabular and survival)
  results.json      what step 4 draws, or {"error": ...} when the run stopped
  <step>.jl, <step>.json   the code and the result of each Next Step run on it
  <id>/             in a run of several datasets: a run of one dataset, as above, for each
\end{lstlisting}

\begin{lstlisting}
# run.toml of a run of one dataset
kind = "series"                     # series, tabular or survival
competition = "tourism_2011"        # the dataset id
folder = "..."                      # only for a dataset of your own: read in place of the id
frequency = "Monthly"               # "" for all its frequencies
sample = 0                          # 0 for all the series; else the number drawn
seed = 1
splits = "all"                      # tabular and survival: "all" the published splits, or "first", the first repeat
started = "2026-11-20 10:15"

# run.toml of a run of several datasets
kind = "series"
datasets = ["tourism_2011", "nn5"]
sample = 0
seed = 1
splits = "all"
started = "2026-11-20 10:15"
\end{lstlisting}

\file{results.json} holds \file{finished}, \file{series}, \file{whole}, \file{level} (the frequency, or
\file{Total}), \file{measures} (sMAPE, MASE, OWA), \file{method} (a score per measure) and \file{benchmarks} (a
\file{name} and \file{scores} each). It also holds \file{plot}, with the series, its last \file{past} values,
\file{actual} and \file{forecast}, and the run's \file{seconds}.

For a tabular or survival dataset, \file{results.json} holds \file{finished}, \file{kind}, \file{response_type},
\file{splits} (the number run), \file{all_splits}, \file{first_repeat}, \file{measures}, \file{best} (\file{lower},
\file{higher} or \file{one} for each measure), \file{method} (the mean over the splits of each measure),
\file{per_split} (the repeat, fold, scores and seconds of each split), \file{published} (a \file{model}, \file{name} and
\file{scores} each), \file{ranks} (for each measure, the method's \file{rank} and the number of runs ranked, \file{of})
and \file{seconds}. The predictions are not kept. A run of several datasets first writes the \file{published.tsv} of every
dataset, reading the published runs of all of them at once, and the \file{run.jl} of each dataset reads its own.
